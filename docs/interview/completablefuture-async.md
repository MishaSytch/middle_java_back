# CompletableFuture и асинхронность


### 1. Что такое CompletableFuture и чем он отличается от Future?

`CompletableFuture` — это класс, представленный в Java 8, который реализует интерфейсы `Future` и `CompletionStage`. Он представляет собой контейнер для значения, которое будет вычислено асинхронно, но в отличие от `Future`, предоставляет мощные возможности для композиции, обработки ошибок и неблокирующей работы.

Ключевые отличия от `Future` (появившегося в Java 5):
- **Композиция:** `Future` не поддерживает создание цепочек асинхронных вызовов. `CompletableFuture` позволяет строить конвейеры с помощью методов вроде `thenApply`, `thenCompose` и других.
- **Неблокирующая обработка:** `Future` предоставляет только блокирующий метод `get()` для получения результата. `CompletableFuture` позволяет зарегистрировать колбэк, который будет вызван по завершении задачи, без блокировки потока.
- **Обработка ошибок:** `Future` не имеет встроенных механизмов для элегантной обработки исключений, кроме как через `try-catch` вокруг `get()`. `CompletableFuture` предлагает методы `exceptionally()`, `handle()` и `whenComplete()`.
- **Ручное завершение:** `CompletableFuture` можно завершить вручную с помощью методов `complete()` или `completeExceptionally()`.

### 2. Какие основные преимущества CompletableFuture перед Future?

Основные преимущества:
- **Декларативность и композиция:** Позволяет описывать сложные асинхронные рабочие процессы в виде цепочек вызовов, что делает код более читаемым и поддерживаемым.
- **Неблокирующая модель (push-based):** Вы получаете уведомление, когда результат готов, вместо того чтобы блокировать поток в ожидании.
- **Гибкое управление потоками:** Поддерживает асинхронное выполнение на разных пулах потоков (с суффиксом `Async`) и позволяет указывать собственный `Executor`.
- **Богатая функциональность:** Включает методы для комбинирования нескольких фьючерсов (`thenCombine`, `allOf`, `anyOf`), обработки исключений и управления таймаутами.

### 3. Как создать CompletableFuture, который уже завершён с результатом?

Для этого используется статический метод `completedFuture()`:
```java
CompletableFuture<String> future = CompletableFuture.completedFuture("готовый результат");
```
Этот метод создает `CompletableFuture`, который немедленно завершается с заданным значением.

### 4. В чём разница между thenApply() и thenCompose()?

- **`thenApply(Function)`** используется для **преобразования** результата. Это аналог `map` в функциональном программировании. Он принимает функцию, которая преобразует результат предыдущего этапа в новое значение. Возвращается `CompletableFuture` с новым типом.
- **`thenCompose(Function)`** используется для **плоского связывания** (flattening). Это аналог `flatMap`. Функция, переданная в `thenCompose`, должна возвращать другой `CompletableFuture`. Это позволяет избежать вложенных структур `CompletableFuture<CompletableFuture<T>>` при последовательном выполнении асинхронных операций, зависящих друг от друга.

### 5. Что делают методы thenAccept() и thenRun()?

Оба метода используются для выполнения действий после завершения предыдущего этапа, но не возвращают нового значения:
- **`thenAccept(Consumer)`**: принимает результат предыдущего этапа и выполняет над ним некоторое действие (потребляет его). Возвращает `CompletableFuture<Void>`.
- **`thenRun(Runnable)`**: не принимает никаких аргументов и просто выполняет заданное действие после завершения предыдущего этапа. Также возвращает `CompletableFuture<Void>`.

### 6. Как обрабатывать исключения в цепочке CompletableFuture?

В `CompletableFuture` есть несколько способов обработки исключений:
- **`exceptionally(Function<Throwable, T>)`**: Выполняется только в случае исключительного завершения. Позволяет вернуть запасное значение (fallback).
- **`handle(BiFunction<T, Throwable, U>)`**: Выполняется **всегда**, независимо от того, завершился ли этап нормально или с исключением. Позволяет обработать и результат, и ошибку, и вернуть новое значение.
- **`whenComplete(BiConsumer<T, Throwable>)`**: Выполняется **всегда**, но, в отличие от `handle`, не изменяет результат. Он предназначен для побочных эффектов (например, логирования) и сохраняет исходный результат или исключение.

### 7. В чём разница между handle(), exceptionally() и whenComplete()?

- **`exceptionally()`**: Срабатывает **только при ошибке**. Возвращает новое значение (восстановление).
- **`handle()`**: Срабатывает **всегда**. Может изменить результат или обработать ошибку, возвращая новое значение.
- **`whenComplete()`**: Срабатывает **всегда**. Выполняет действие (например, логирование), но **не изменяет** исходный результат или исключение. Если исходный этап завершился ошибкой, она будет передана дальше.

### 8. Как комбинировать результаты нескольких CompletableFuture?

Для комбинирования двух фьючерсов используется `thenCombine()`. Он принимает другой `CompletableFuture` и `BiFunction`, которая обрабатывает результаты обоих, когда они оба завершатся. Для комбинирования большего числа фьючерсов используются `allOf()` и `anyOf()`.

### 9. Что делает метод allOf() и когда его использовать?

`CompletableFuture.allOf(CompletableFuture<?>... cfs)` возвращает новый `CompletableFuture<Void>`, который завершается, когда **все** переданные фьючерсы завершатся. Его удобно использовать, когда нужно дождаться выполнения нескольких независимых асинхронных задач, прежде чем продолжить. Важно помнить, что он не возвращает агрегированный результат — результаты нужно извлекать из исходных фьючерсов отдельно.

### 10. Что делает метод anyOf() и в каких случаях он полезен?

`CompletableFuture.anyOf(CompletableFuture<?>... cfs)` возвращает новый `CompletableFuture<Object>`, который завершается, как только **любой** из переданных фьючерсов завершится (нормально или с исключением). Полезен в сценариях, где нужно получить самый быстрый ответ, например, при запросе к нескольким репликам сервиса, и использовать первый пришедший результат. Поскольку тип возвращаемого значения — `Object`, может потребоваться приведение типа.

### 11. В чём разница между thenApply() и thenApplyAsync()?

Разница заключается в потоке, в котором выполняется функция:
- **`thenApply()`**: выполняется в потоке, который завершил предыдущий этап, или в текущем потоке, если предыдущий этап уже завершен.
- **`thenApplyAsync()`**: выполняется асинхронно в потоке из `ForkJoinPool.commonPool()` (по умолчанию) или из указанного `Executor`.

### 12. Какой пул потоков используется по умолчанию для async методов?

По умолчанию методы с суффиксом `Async` (например, `thenApplyAsync`, `supplyAsync`) используют общий пул `ForkJoinPool.commonPool()`. Его размер по умолчанию равен количеству доступных процессоров минус один, и он оптимизирован для коротких задач, интенсивно использующих CPU.

### 13. Как указать свой Executor для CompletableFuture?

Вы можете передать свой `Executor` в качестве дополнительного аргумента в методы, которые создают или асинхронно обрабатывают `CompletableFuture`. Например:
```java
ExecutorService customExecutor = Executors.newFixedThreadPool(10);
CompletableFuture.supplyAsync(() -> "task", customExecutor);
future.thenApplyAsync(result -> result + " processed", customExecutor);
```
Это позволяет использовать собственный пул потоков, настроенный под конкретные задачи (например, для операций ввода-вывода).

### 14. Что такое блокирующий код и как его отличить от неблокирующего?

- **Блокирующий код**: Поток выполнения приостанавливается и ждет завершения операции (например, чтения из сети, получения блокировки, вызова `Future.get()`), не выполняя при этом другой полезной работы.
- **Неблокирующий код**: Поток не приостанавливается в ожидании результата. Вместо этого он регистрирует колбэк (например, через `thenApply`, `thenAccept`) и продолжает выполнение. Когда результат будет готов, колбэк будет вызван в подходящем потоке.

### 15. Почему важно избегать блокирующих операций в CompletableFuture?

Блокирующие операции в асинхронном конвейере сводят на нет все преимущества `CompletableFuture`. Если вы вызываете `join()` или `get()` внутри цепочки, вы блокируете поток из пула, который мог бы использоваться для выполнения других задач. Это может быстро привести к **истощению пула потоков** (thread starvation) и потере производительности, особенно в высоконагруженных системах.

### 16. Как правильно выполнить несколько параллельных запросов к микросервисам?

Правильный подход — использовать `CompletableFuture` для асинхронного запуска всех запросов, а затем дождаться их завершения:
```java
CompletableFuture<ResponseA> futureA = CompletableFuture.supplyAsync(() -> callServiceA());
CompletableFuture<ResponseB> futureB = CompletableFuture.supplyAsync(() -> callServiceB());

// Дождаться завершения обоих
CompletableFuture<Void> allFutures = CompletableFuture.allOf(futureA, futureB);

// Затем обработать результаты
allFutures.thenRun(() -> {
    ResponseA a = futureA.join(); // здесь join() безопасен, т.к. allOf уже завершен
    ResponseB b = futureB.join();
    // ... объединить результаты
});
```
Это позволяет запустить оба запроса параллельно и обработать результаты после завершения обоих, не блокируя поток на время их выполнения.

### 17. Что делает метод supplyAsync() и когда его использовать?

`CompletableFuture.supplyAsync(Supplier<U>)` запускает асинхронную задачу, которая **возвращает результат**. Он принимает функциональный интерфейс `Supplier`, который не имеет аргументов, но возвращает значение. Используется для асинхронного выполнения вычислений или операций ввода-вывода, результатом которых является значение.

### 18. Как отменить выполнение CompletableFuture?

Вы можете попытаться отменить `CompletableFuture` с помощью метода `cancel(boolean mayInterruptIfRunning)`. Однако, в отличие от `Future`, отмена `CompletableFuture` не прерывает выполняющуюся задачу, а просто переводит сам `CompletableFuture` в состояние "отменен". Это равносильно вызову `completeExceptionally(new CancellationException())`.

### 19. Что произойдёт, если в цепочке CompletableFuture возникнет исключение?

Если на каком-либо этапе цепочки возникает исключение (и оно не обработано), то все последующие зависимые этапы (например, `thenApply`, `thenAccept`) **пропускаются**, и `CompletableFuture` завершается исключительно. Исключение распространяется вниз по цепочке, пока не будет обработано одним из методов (`exceptionally`, `handle` и т.д.).

### 20. Можно ли повторно использовать один CompletableFuture в нескольких цепочках?

Да, `CompletableFuture` можно использовать в нескольких цепочках. Однако важно понимать, что `CompletableFuture` **одноразовый**: после завершения его состояние (результат или исключение) фиксируется. Все цепочки, присоединенные к нему, получат это итоговое состояние. Вы не можете "перезапустить" один и тот же `CompletableFuture` с новым вычислением. Для каждой новой асинхронной операции создается новый `CompletableFuture`.

### 21. Как реализовать timeout для CompletableFuture?

Начиная с Java 9, есть встроенные методы:
- **`orTimeout(long timeout, TimeUnit unit)`**: Если `CompletableFuture` не завершится за указанное время, он завершится исключительно с `TimeoutException`.
- **`completeOnTimeout(T value, long timeout, TimeUnit unit)`**: Если `CompletableFuture` не завершится за указанное время, он завершится с заданным значением `value`.

Пример:
```java
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> longRunningTask())
    .orTimeout(5, TimeUnit.SECONDS);
```

### 22. Что делает метод orTimeout() в Java 9+?

Метод `orTimeout()` — это метод экземпляра `CompletableFuture`, который устанавливает таймаут. Если исходный `CompletableFuture` не завершится в течение заданного времени, он будет завершен исключением `TimeoutException`. Это декларативный способ добавить таймаут в асинхронный конвейер.

### 23. В чём разница между thenCombine() и thenCompose()?

- **`thenCombine()`**: используется для **параллельного** выполнения двух независимых `CompletableFuture` и последующего объединения их результатов с помощью `BiFunction`, когда оба завершатся.
- **`thenCompose()`**: используется для **последовательного** выполнения асинхронных операций, где результат первой операции используется для запуска второй, которая возвращает новый `CompletableFuture`. Это позволяет избежать вложенности.

### 24. Как тестировать код с CompletableFuture?

Тестирование асинхронного кода имеет свои особенности:
- **Избегайте `Thread.sleep()`**: Это ненадежный и медленный способ ожидания.
- **Используйте библиотеки, такие как Awaitility**: Они позволяют элегантно ждать выполнения условия (например, `future.isDone()` или получения определенного результата) с заданным таймаутом, опрашивая состояние через определенные интервалы.
- **Проверяйте, что метод не блокируется**: Если вы тестируете метод, который должен возвращать `CompletableFuture` без блокировки, убедитесь, что он не вызывает внутри `join()` или `get()`.
- **Тестируйте обработку ошибок**: Убедитесь, что ваши цепочки корректно обрабатывают исключения.

### 25. В каких случаях лучше использовать CompletableFuture, а в каких - реактивное программирование?

- **`CompletableFuture`**: Идеально подходит для моделирования **однократных** асинхронных операций, которые возвращают **один** результат (или `Void`). Он хорошо ложится на задачи, где нужно выполнить запрос, скомбинировать пару ответов и вернуть итог. Это более простой и легковесный инструмент, встроенный в JDK.
- **Реактивное программирование (Reactive Streams, Project Reactor, RxJava)**: Лучше подходит для работы с **потоками** данных (0, 1 или N элементов), которые могут генерироваться с течением времени. Оно предлагает богатый набор операторов для фильтрации, преобразования, буферизации и управления backpressure (обратным давлением). Это более мощный, но и более сложный инструмент, который часто используется в высоконагруженных системах и при работе с потоковыми данными.

### 26. Что делает метод join() и чем он отличается от get()?

Оба метода блокируют вызывающий поток до завершения `CompletableFuture` и возвращают результат.
- **`get()`**: Объявлен в интерфейсе `Future` и может выбрасывать проверяемые исключения `InterruptedException` и `ExecutionException`.
- **`join()`**: Объявлен в `CompletableFuture` и не выбрасывает проверяемых исключений. Если `CompletableFuture` завершился исключительно, `join()` выбрасывает непроверяемое исключение `CompletionException`.

### 27. Можно ли вручную завершить CompletableFuture результатом?

Да, это одна из ключевых возможностей `CompletableFuture`. Вы можете создать "пустой" `CompletableFuture` с помощью `new CompletableFuture<>()` и позже завершить его из любого потока, вызвав метод `complete(T value)` для успешного завершения или `completeExceptionally(Throwable ex)` для завершения с ошибкой.

### 28. Как реализовать retry логику с помощью CompletableFuture?

Прямого встроенного метода для retry в `CompletableFuture` нет. Логику повторных попыток можно реализовать, обернув асинхронную операцию в метод, который при возникновении исключения создает новый `CompletableFuture` для повторной попытки. Это можно сделать рекурсивно, используя `handle()` или `exceptionally()` для перехвата ошибки и инициирования новой попытки, возможно, с задержкой.

Пример концептуальной реализации:
```java
public static <T> CompletableFuture<T> retry(Supplier<CompletableFuture<T>> operation, int retries) {
    return operation.get().handle((result, ex) -> {
        if (ex != null && retries > 0) {
            // Повторная попытка
            return retry(operation, retries - 1);
        } else if (ex != null) {
            throw new CompletionException(ex);
        } else {
            return CompletableFuture.completedFuture(result);
        }
    }).thenCompose(Function.identity());
}
```
Этот код при ошибке рекурсивно создает новый `CompletableFuture` для повторной попытки, пока не исчерпаются `retries`.
