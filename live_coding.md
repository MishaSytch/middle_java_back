# Java Middle: 200 задач live coding с решениями

> Сборник для секции live coding собеседований на позицию Middle Java. Форматы — как в реальном интервью: написать функцию с нуля, найти баг, отрефакторить, «что выведет», мини-дизайн класса, многопоточность, переделка на стримы, реализация структуры данных с нуля, тесты.

## Условные обозначения

- Java 17 (LTS): используются `record`, switch-выражения, `sealed`; где нужна конкретная версия — помечено.
- Считается, что `import java.util.*;` уже сделан; нестандартные импорты показаны явно.
- Сниппеты компилируемы: методы и классы без `main`.
- Вспомогательные типы (`ListNode`, `TreeNode`, `Employee`) описаны один раз в начале раздела.
- Сложность указывается там, где она часть ответа — её спрашивают почти всегда.

## Как тренироваться

1. Проговаривай уточнения вслух: диапазоны значений, дубликаты, пустой вход, можно ли менять вход.
2. Озвучивай подход и сложность ДО написания кода — интервьюер оценивает мышление, а не только результат.
3. Перечисли edge cases: пустой массив, один элемент, отрицательные числа, переполнение.
4. Пиши код поэтапно и рассуждай параллельно; не молчи.
5. Жди follow-up: «а можно без доп. памяти?», «а если данные не влезают в RAM?», «а если потоков десять?» — многие указаны в решениях.

## Раздел 1. Массивы и два указателя
> Что проверяют: уверенная работа с индексами, инварианты цикла, замена O(n²) на O(n), аккуратность с границами.

<a id="r1-t1"></a>
**1. [Классика] Two Sum.**
Дан массив чисел и target. Вернуть индексы двух чисел, дающих в сумме target.
```java
static int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();       // значение -> индекс
    for (int i = 0; i < nums.length; i++) {
        Integer j = seen.get(target - nums[i]);
        if (j != null) return new int[]{j, i};
        seen.put(nums[i], i);
    }
    throw new IllegalArgumentException("пары нет");
}
```
Сложность O(n) время / O(n) память. Фоллоу-апы: «если массив отсортирован?» — два указателя с концов, O(1) памяти; «сколько пар?» — копим частоты и комбинаторика.

<a id="r1-t2"></a>
**2. [Классика] Максимальная сумма подотрезка (алгоритм Кадана).**
```java
static int maxSubArray(int[] a) {
    int best = a[0], cur = a[0];
    for (int i = 1; i < a.length; i++) {
        cur = Math.max(a[i], cur + a[i]);   // продолжаем или начинаем заново
        best = Math.max(best, cur);
    }
    return best;
}
```
O(n), один проход. Фоллоу-ап: вернуть ещё и границы отрезка — храним старт текущего при «начали заново».

<a id="r1-t3"></a>
**3. [Классика] Число подотрезков с суммой ровно k.**
Массив может содержать отрицательные — окно тут не работает.
```java
static int countSubarrays(int[] a, int k) {
    Map<Long, Integer> freq = new HashMap<>(); // префиксная сумма -> сколько раз встречалась
    freq.put(0L, 1);
    long sum = 0;
    int count = 0;
    for (int x : a) {
        sum += x;
        count += freq.getOrDefault(sum - k, 0);
        freq.merge(sum, 1, Integer::sum);
    }
    return count;
}
```
O(n). Ключевой факт: сумма отрезка = разность двух префиксов. Почему окно не работает с отрицательными — обязательно объяснить.

<a id="r1-t4"></a>
**4. [Классика] Произведение всех элементов кроме текущего.**
Без деления. `{"1","2","3","4"}` → `{24,12,8,6}`.
```java
static int[] productExceptSelf(int[] a) {
    int n = a.length;
    int[] res = new int[n];
    res[0] = 1;
    for (int i = 1; i < n; i++) res[i] = res[i - 1] * a[i - 1]; // произведения слева
    int right = 1;
    for (int i = n - 1; i >= 0; i--) {                          // домножаем произведениями справа
        res[i] *= right;
        right *= a[i];
    }
    return res;
}
```
O(n), O(1) дополнительной памяти (кроме ответа). Фоллоу-ап: как поведёт себя деление при нуле в массиве — почему подход «перемножить всё и делить» ломается.

<a id="r1-t5"></a>
**5. [Классика] Сдвинуть нули в конец, сохранив порядок ненулевых.**
```java
static void moveZeroes(int[] a) {
    int w = 0;                                   // позиция для следующего ненулевого
    for (int i = 0; i < a.length; i++)
        if (a[i] != 0) {
            int t = a[w]; a[w++] = a[i]; a[i] = t;
        }
}
```
O(n), обмены in-place. Вариант без лишних свопов — двойной указатель с записью и последующим занулением хвоста.

<a id="r1-t6"></a>
**6. [Классика] Поворот массива на k вправо на месте.**
```java
static void rotate(int[] a, int k) {
    int n = a.length;
    k %= n;
    reverse(a, 0, n - 1);   // весь массив
    reverse(a, 0, k - 1);   // первые k
    reverse(a, k, n - 1);   // хвост
}
private static void reverse(int[] a, int lo, int hi) {
    while (lo < hi) { int t = a[lo]; a[lo++] = a[hi]; a[hi--] = t; }
}
```
O(n) обменов, O(1) памяти. Обязательно обработать `k > n`. Альтернатива — циклические замены (juggling algorithm), спросить не любят, но упомянуть стоит.

<a id="r1-t7"></a>
**7. [Классика] Удалить дубликаты из отсортированного массива на месте.**
Вернуть новую «длину»; хвост значения не имеет.
```java
static int removeDuplicates(int[] a) {
    if (a.length == 0) return 0;
    int w = 1;
    for (int i = 1; i < a.length; i++)
        if (a[i] != a[w - 1]) a[w++] = a[i];
    return w;
}
```
Два указателя: медленный `w` — граница «уникального» префикса. Фоллоу-ап: разрешено не более 2 повторов — сравнивать с `a[w - 2]`.

<a id="r1-t8"></a>
**8. [Классика] Найти пропущенное число из 1..n.**
В массиве n−1 различных чисел из диапазона 1..n.
```java
static int missing(int[] a) {
    int n = a.length + 1;
    long sum = (long) n * (n + 1) / 2;   // n может дать переполнение int — считаем в long
    for (int x : a) sum -= x;
    return (int) sum;
}
```
XOR-вариант: `r ^= i ^ a[i]` для всех i — не боится переполнения. Оба O(n)/O(1).

<a id="r1-t9"></a>
**9. [Классика|hard] Найти единственный дубликат.**
n+1 чисел из диапазона 1..n, ровно одно число повторяется. Массив менять нельзя, доп. память O(1).
```java
static int findDuplicate(int[] a) {
    int slow = a[0], fast = a[a[0]];       // Флойд: массив — неявный связный список a[i] -> a[a[i]]
    while (slow != fast) { slow = a[slow]; fast = a[a[fast]]; }
    slow = 0;                              // вторая фаза — вход в цикл
    while (slow != fast) { slow = a[slow]; fast = a[fast]; }
    return slow;
}
```
Идея: индекс → значение трактуем как ссылку; повторное число = вход в цикл. Если разрешено менять массив — проще пометить знак у `a[abs(x)]`.

<a id="r1-t10"></a>
**10. [Классика] Контейнер с водой: максимум площади.**
Высоты стенок; выбрать две, максимизировать `min(h[i], h[j]) * (j - i)`.
```java
static int maxArea(int[] h) {
    int lo = 0, hi = h.length - 1, best = 0;
    while (lo < hi) {
        best = Math.max(best, (hi - lo) * Math.min(h[lo], h[hi]));
        if (h[lo] < h[hi]) lo++; else hi--;   // двигаем МЕНЬШУЮ стенку
    }
    return best;
}
```
O(n). Обоснование: сдвиг большей стенки никогда не увеличит площадь (лимитирует меньшая).

## Раздел 2. Строки и скользящее окно
> Что проверяют: работа с char/кодами, понимание неизменяемости String, окно как приём, аккуратность с UTF-16 суррогатами.

<a id="r2-t1"></a>
**1. [Классика] Анаграммы.**
```java
static boolean isAnagram(String s, String t) {
    if (s.length() != t.length()) return false;
    int[] f = new int[26];
    for (int i = 0; i < s.length(); i++) {
        f[s.charAt(i) - 'a']++;
        f[t.charAt(i) - 'a']--;
    }
    for (int x : f) if (x != 0) return false;
    return true;
}
```
O(n). Фоллоу-ап: произвольный Unicode — `HashMap<Integer,Integer>` по `codePoints()`; сортировка O(n log n) — хуже по константе.

<a id="r2-t2"></a>
**2. [Классика] Самая длинная подстрока без повторяющихся символов.**
```java
static int lengthOfLongestSubstring(String s) {
    int[] last = new int[128];
    Arrays.fill(last, -1);
    int best = 0, start = 0;                     // start — левая граница окна
    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (last[c] >= start) start = last[c] + 1;  // повтор внутри окна — сдвигаем левую границу
        last[c] = i;
        best = Math.max(best, i - start + 1);
    }
    return best;
}
```
O(n) — каждый индекс входит и выходит из окна максимум один раз. Классика окна; уметь объяснить инвариант «в окне нет дубликатов».

<a id="r2-t3"></a>
**3. [Классика] Индекс первого неповторяющегося символа.**
```java
static int firstUnique(String s) {
    int[] f = new int[26];
    for (char c : s.toCharArray()) f[c - 'a']++;
    for (int i = 0; i < s.length(); i++)
        if (f[s.charAt(i) - 'a'] == 1) return i;
    return -1;
}
```
Два прохода: O(n). Одним проходом по потоку символов — см. раздел 3, задача про FirstNonRepeating.

<a id="r2-t4"></a>
**4. [Классика] Сжатие строки на месте.**
`"aaabbc"` → `"a3b2c"`; вернуть новую длину (символ + число повторов, если больше 1).
```java
static int compress(char[] a) {
    int w = 0;
    for (int i = 0; i < a.length; ) {
        char c = a[i];
        int j = i;
        while (j < a.length && a[j] == c) j++;
        a[w++] = c;
        int len = j - i;
        if (len > 1)
            for (char d : String.valueOf(len).toCharArray()) a[w++] = d;
        i = j;
    }
    return w;
}
```
O(n). Число может быть многозначным — писать по цифрам.

<a id="r2-t5"></a>
**5. [Классика] Перевернуть порядок слов в строке.**
`"  hello   world "` → `"world hello"`.
```java
static String reverseWords(String s) {
    String[] words = s.trim().split("\\s+");
    StringBuilder sb = new StringBuilder();
    for (int i = words.length - 1; i >= 0; i--) {
        sb.append(words[i]);
        if (i > 0) sb.append(' ');
    }
    return sb.toString();
}
```
Фоллоу-ап: сделать за O(1) памяти над char[] — два указателя: развернуть всю строку, затем каждое слово, попутно уплотняя пробелы.

<a id="r2-t6"></a>
**6. [Классика] Палиндром с пропуском не-букв.**
`"A man, a plan, a canal: Panama"` → true.
```java
static boolean isPalindrome(String s) {
    for (int i = 0, j = s.length() - 1; i < j; ) {
        if (!Character.isLetterOrDigit(s.charAt(i))) i++;
        else if (!Character.isLetterOrDigit(s.charAt(j))) j--;
        else if (Character.toLowerCase(s.charAt(i++)) != Character.toLowerCase(s.charAt(j--))) return false;
    }
    return true;
}
```
O(n), O(1). Регекс-вариант `s.replaceAll("\\W","")` — дополнительная строка и проход, сказать про это.

<a id="r2-t7"></a>
**7. [Классика|hard] parseInt руками с ограничением по переполнению.**
Как `Integer.parseInt`, но: пробелы по краям, необязательный знак, обрыв на первом нецифровом символе, клэмп в границы int при переполнении.
```java
static int parseInt(String s) {
    s = s.strip();
    if (s.isEmpty()) return 0;
    int sign = 1, i = 0;
    char c0 = s.charAt(0);
    if (c0 == '+' || c0 == '-') { if (c0 == '-') sign = -1; i = 1; }
    long acc = 0;
    for (; i < s.length(); i++) {
        char c = s.charAt(i);
        if (c < '0' || c > '9') break;
        acc = acc * 10 + (c - '0');
        if (acc > Integer.MAX_VALUE + 1L) break;   // дальше смысла копить нет
    }
    long res = sign * acc;
    if (res > Integer.MAX_VALUE) return Integer.MAX_VALUE;
    if (res < Integer.MIN_VALUE) return Integer.MIN_VALUE;
    return (int) res;
}
```
Скоп значения — в `long` (или ручная проверка `res > MAX/10`). Обязательно проговорить `Integer.MIN_VALUE` по модулю больше `MAX` на 1.

<a id="r2-t8"></a>
**8. [Классика] Римские числа в int.**
```java
static int romanToInt(String s) {
    Map<Character, Integer> v = Map.of('I', 1, 'V', 5, 'X', 10, 'L', 50, 'C', 100, 'D', 500, 'M', 1000);
    int sum = 0;
    for (int i = 0; i < s.length(); i++) {
        int cur = v.get(s.charAt(i));
        sum += (i + 1 < s.length() && cur < v.get(s.charAt(i + 1))) ? -cur : cur; // IV, IX, XL...
    }
    return sum;
}
```
O(n). Инвариант: вычитание — только когда текущая цифра меньше следующей.

<a id="r2-t9"></a>
**9. [Классика] Run-length кодирование и декодирование.**
```java
static String encode(String s) {
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < s.length(); ) {
        char c = s.charAt(i);
        int j = i;
        while (j < s.length() && s.charAt(j) == c) j++;
        sb.append(c).append(j - i);
        i = j;
    }
    return sb.toString();
}
static String decode(String s) {                    // "a10" — счётчик многозначный
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < s.length(); ) {
        char c = s.charAt(i++);
        int n = 0;
        while (i < s.length() && Character.isDigit(s.charAt(i)))
            n = n * 10 + (s.charAt(i++) - '0');
        sb.append(String.valueOf(c).repeat(n));      // Java 11+
    }
    return sb.toString();
}
```
Проговорить ограничение формата: исходный алфавит не должен содержать цифр — иначе нужно экранирование.

<a id="r2-t10"></a>
**10. [Классика] Изоморфные строки.**
`"paper"`/`"title"` → true (взаимно однозначная замена символов).
```java
static boolean isIsomorphic(String s, String t) {
    int[] m1 = new int[128], m2 = new int[128];
    Arrays.fill(m1, -1);
    Arrays.fill(m2, -1);
    for (int i = 0; i < s.length(); i++) {
        char a = s.charAt(i), b = t.charAt(i);
        if (m1[a] != -1 && m1[a] != b) return false;
        if (m2[b] != -1 && m2[b] != a) return false;
        m1[a] = b; m2[b] = a;
    }
    return true;
}
```
Две карты: s→t И t→s. Частая ошибка кандидатов — проверять только одно направление.

## Раздел 3. Хеширование и частоты
> Что проверяют: выбор HashMap/HashSet как инструмента O(1)-поиска, аккуратность с компараторами, бинальный поиск по куче.

<a id="r3-t1"></a>
**1. [Классика] K самых частых элементов.**
```java
static int[] topKFrequent(int[] a, int k) {
    Map<Integer, Integer> f = new HashMap<>();
    for (int x : a) f.merge(x, 1, Integer::sum);
    PriorityQueue<int[]> min = new PriorityQueue<>(Comparator.comparingInt(p -> p[1])); // мин-куча размера k
    for (Map.Entry<Integer, Integer> e : f.entrySet()) {
        min.offer(new int[]{e.getKey(), e.getValue()});
        if (min.size() > k) min.poll();          // выталкиваем самый редкий
    }
    int[] res = new int[k];
    for (int i = k - 1; i >= 0; i--) res[i] = min.poll()[0];
    return res;
}
```
O(n log k). Фоллоу-ап: bucket sort по частоте — O(n) время и память: индекс = частота.

**2. [Классика] Сгруппировать анаграммы.**

**3. [Классика|hard] Самая длинная последовательность подряд идущих чисел.**
`{100,4,200,1,3,2}` → 4 (1,2,3,4). Сортировка — O(n log n); нужно O(n).
```java
static int longestConsecutive(int[] a) {
    Set<Integer> set = new HashSet<>();
    for (int x : a) set.add(x);
    int best = 0;
    for (int x : set) {
        if (set.contains(x - 1)) continue;    // начинаем только с начала последовательности
        int len = 1;
        while (set.contains(x + len)) len++;
        best = Math.max(best, len);
    }
    return best;
}
```
Каждый элемент посещается максимум дважды — суммарно O(n), хотя вложенный while. Уметь доказать.

<a id="r3-t4"></a>
**4. [Дизайн] Первый неповторяющийся символ в потоке.**
Символы приходят по одному; в любой момент — запрос «первый неповторяющийся».
```java
class FirstNonRepeating {
    private final Set<Character> repeated = new HashSet<>();
    private final LinkedHashSet<Character> once = new LinkedHashSet<>(); // сохраняет порядок поступления
    public synchronized void add(char c) {
        if (!once.add(c)) { once.remove(c); repeated.add(c); }
    }
    public synchronized Character first() {
        return once.isEmpty() ? null : once.iterator().next();
    }
}
```
O(1) на операцию. Фоллоу-ап: удалять из `once` только реально существующий ключ (иначе `LinkedHashSet.remove` отсутствующего — no-op, безопасно, но проговорить).

**5. [Классика] Пересечение массивов с учётом кратности.**
```java
static int[] intersect(int[] a, int[] b) {
    Map<Integer, Integer> f = new HashMap<>();
    for (int x : a) f.merge(x, 1, Integer::sum);
    List<Integer> res = new ArrayList<>();
    for (int x : b) {
        int left = f.getOrDefault(x, 0);
        if (left > 0) { res.add(x); f.put(x, left - 1); }
    }
    return res.stream().mapToInt(Integer::intValue).toArray();
}
```

## Раздел 4. Сортировка и бинарный поиск
> Что проверяют: Comparator API, инварианты бинарного поиска, переполнение mid, аккуратность на границах.

<a id="r4-t1"></a>
**1. [Классика] Многоуровневая сортировка объектов.**
Сотрудники: по убыванию зарплаты, при равенстве — по имени.
```java
record Employee(String name, String dept, String city, int salary) { }

List<Employee> sorted = new ArrayList<>(employees);
sorted.sort(Comparator.comparingInt(Employee::salary).reversed()
        .thenComparing(Employee::name));
```
Ключевое: `thenComparing` комбинатор; `reversed()` инвертирует только предыдущий уровень, а не всю цепочку — любимый вопрос-ловушка.

<a id="r4-t2"></a>
**2. [Классика] Первое и последнее вхождение в отсортированном массиве.**
```java
static int first(int[] a, int t) {
    int lo = 0, hi = a.length - 1, res = -1;
    while (lo <= hi) {
        int mid = (lo + hi) >>> 1;               // беззнаковый сдвиг: (lo+hi)/2 может переполниться
        if (a[mid] >= t) { if (a[mid] == t) res = mid; hi = mid - 1; }
        else lo = mid + 1;
    }
    return res;
}
```
Последнее — симметрично (`<=`, сдвигаем `lo`). Двоится до сходимости к границе; O(log n).

<a id="r4-t3"></a>
**3. [Классика|hard] Поиск в повёрнутом отсортированном массиве.**
```java
static int searchRotated(int[] a, int t) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = (lo + hi) >>> 1;
        if (a[mid] == t) return mid;
        if (a[lo] <= a[mid]) {                                   // левая половина отсортирована
            if (a[lo] <= t && t < a[mid]) hi = mid - 1; else lo = mid + 1;
        } else {                                                 // правая отсортирована
            if (a[mid] < t && t <= a[hi]) lo = mid + 1; else hi = mid - 1;
        }
    }
    return -1;
}
```
Инвариант: хотя бы одна половина отсортирована — определяем по `a[lo] <= a[mid]`. O(log n).

<a id="r4-t4"></a>
**4. [Классика] Слияние двух отсортированных массивов на месте.**
В `a` длины m+n первые m отсортированы, дальше место; `b` длины n.
```java
static void merge(int[] a, int m, int[] b, int n) {
    int i = m - 1, j = n - 1, w = m + n - 1;     // запись с конца — не затираем ещё не перенесённое
    while (j >= 0) {
        if (i >= 0 && a[i] > b[j]) a[w--] = a[i--];
        else a[w--] = b[j--];
    }
}
```
Классический приём «писать с хвоста». Спросить: почему с начала нельзя.

<a id="r4-t5"></a>
**5. [Классика] Сортировка слов по кастомному алфавиту.**
```java
static String[] sortByAlphabet(String[] words, String order) {
    int[] rank = new int[128];
    for (int i = 0; i < order.length(); i++) rank[order.charAt(i)] = i;
    Comparator<String> byOrder = (x, y) -> {
        int n = Math.min(x.length(), y.length());
        for (int i = 0; i < n; i++) {
            int d = rank[x.charAt(i)] - rank[y.charAt(i)];
            if (d != 0) return d;
        }
        return x.length() - y.length();
    };
    Arrays.sort(words, byOrder);
    return words;
}
```
Предвычислить ранги → компаратор O(len). Сортировка целиком O(n log n · len).

<a id="r4-t6"></a>
**6. [Классика|hard] K-й по величине без полной сортировки (quickselect).**
```java
static final java.util.Random RND = new java.util.Random();

static int kthLargest(int[] a, int k) {
    int target = a.length - k;                    // индекс в отсортированном по возрастанию
    int lo = 0, hi = a.length - 1;
    while (true) {
        int p = partition(a, lo, hi);
        if (p == target) return a[p];
        if (p < target) lo = p + 1; else hi = p - 1;
    }
}
private static int partition(int[] a, int lo, int hi) {
    int idx = lo + RND.nextInt(hi - lo + 1);      // случайный опорный — защита от худшего случая
    swap(a, idx, hi);
    int pivot = a[hi], w = lo;
    for (int i = lo; i < hi; i++)
        if (a[i] < pivot) swap(a, i, w++);
    swap(a, w, hi);
    return w;
}
private static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
```
Среднее O(n), худшее O(n²). Альтернатива для собеса: мин-куча размера k — O(n log k), гарантированно; в потоке данных — только куча.

<a id="r4-t7"></a>
**7. [Классика] Компаратор с null-полями.**
```java
Comparator<Employee> c = Comparator

```
`nullsLast/nullsFirst` оборачивают любой компаратор; без них NPE на первом же null. Стандартная задача «а у нас в данных бывают null».

**8. [Классика] Позиция вставки в отсортированный массив.**

## Раздел 5. Числа и битовые операции
> Что проверяют: переполнение int, модульная арифметика, битовые трюки и границы примитивов.

<a id="r5-t1"></a>
**1. [Классика] Решето Эратосфена.**
Все простые до n.
```java
static boolean[] sieve(int n) {
    boolean[] composite = new boolean[n + 1];
    for (int p = 2; (long) p * p <= n; p++)      // p*p — уже int*int: привести к long
        if (!composite[p])
            for (int q = p * p; q <= n; q += p) composite[q] = true;
    return composite;                             // !composite[i] && i >= 2 => простое
}
```
O(n log log n). Начинать зачёркивание с p² — всё меньшее уже зачёркнуто меньшими делителями.

<a id="r5-t2"></a>
**2. [Классика] НОД/НОК и сокращение дроби.**
```java
static int gcd(int a, int b) {
    while (b != 0) { int t = a % b; a = b; b = t; }
    return Math.abs(a);
}
static int lcm(int a, int b) { return a / gcd(a, b) * b; }   // сначала делим — против переполнения
record Frac(int num, int den) {
    Frac {
        if (den == 0) throw new IllegalArgumentException("den = 0");
        if (den < 0) { num = -num; den = -den; }             // знак держим в числителе
        int g = gcd(Math.abs(num), den);
        num /= g; den /= g;
    }
}
```
Евклид за O(log min(a,b)). Проговорить: `a / gcd * b`, а не `a * b / gcd` — второе переполняется раньше.

<a id="r5-t3"></a>
**3. [Классика] Число, встречающееся один раз, остальные — дважды.**
```java
static int singleNumber(int[] a) {
    int r = 0;
    for (int x : a) r ^= x;      // пары взаимоуничтожаются: x ^ x = 0
    return r;
}
```
O(n)/O(1). Фоллоу-ап (hard): если два числа встречаются по разу — XOR всех даёт `x ^ y`; по младшему установленному биту результата делим массив на две группы и XOR-им каждую отдельно.

<a id="r5-t4"></a>
**4. [Классика] Быстрое возведение в степень по модулю.**
```java
static long powMod(long base, long exp, long mod) {
    long res = 1;
    base %= mod;
    while (exp > 0) {
        if ((exp & 1) == 1) res = res * base % mod;
        base = base * base % mod;
        exp >>= 1;
    }
    return res;
}
```
O(log exp) умножений. Умножения — в long, если mod близок к 10^9: `int*int` переполнится.

<a id="r5-t5"></a>
**5. [Классика|hard] Перевернуть число с контролем переполнения.**
```java
static int reverse(int x) {
    int res = 0;
    while (x != 0) {
        int digit = x % 10;
        x /= 10;
        if (res > Integer.MAX_VALUE / 10 || (res == Integer.MAX_VALUE / 10 && digit > 7)) return 0;
        if (res < Integer.MIN_VALUE / 10 || (res == Integer.MIN_VALUE / 10 && digit < -8)) return 0;
        res = res * 10 + digit;
    }
    return res;
}
```
Проверять ДО умножения. `MIN_VALUE = -2147483648` — последняя цифра -8, у MAX — 7: поэтому константы 7 и -8. Сказать про `Math.multiplyExact/addExact` как альтернативу через ArithmeticException.

<a id="r5-t6"></a>
**6. [Классика] Битовые трюки: степень двойки, подсчёт битов, обмен.**
```java
static boolean isPow2(int x) { return x > 0 && (x & (x - 1)) == 0; }   // у степени двойки один бит
static int countBits(int x) {                                            // Керниган
    int n = 0;
    while (x != 0) { x &= x - 1; n++; }                                  // каждый шаг гасит младший установленный бит
    return n;
}
// в проде: Integer.bitCount(x) — табличная реализация
static void swap(int[] a, int i, int j) {   // XOR-обмен — только показать понимание битов
    if (i == j) return;                    // без проверки затрёт значение нулём!
    a[i] ^= a[j]; a[j] ^= a[i]; a[i] ^= a[j];
}
```
Уметь объяснить каждый трюк на примере на бумаге — интервьюер любит «покажи на числе 12».

## Раздел 6. Рекурсия и комбинаторика
> Что проверяют: выход из рекурсии, копирование состояния при возврате (backtracking), оценка числа путей.

<a id="r6-t1"></a>
**1. [Классика] Все перестановки.**
```java
static List<List<Integer>> permutations(int[] a) {
    List<List<Integer>> res = new ArrayList<>();
    backtrack(a, new boolean[a.length], new ArrayList<>(), res);
    return res;
}
private static void backtrack(int[] a, boolean[] used, List<Integer> cur, List<List<Integer>> res) {
    if (cur.size() == a.length) { res.add(new ArrayList<>(cur)); return; } // КОПИЯ!
    for (int i = 0; i < a.length; i++) {
        if (used[i]) continue;
        used[i] = true;
        cur.add(a[i]);
        backtrack(a, used, cur, res);
        cur.remove(cur.size() - 1);            // откат состояния
        used[i] = false;
    }
}
```
O(n·n!). Главная ошибка — положить в результат сам `cur` без копии: он продолжит мутировать.

<a id="r6-t2"></a>
**2. [Классика] Все подмножества (power set).**
```java
static List<List<Integer>> subsets(int[] a) {
    List<List<Integer>> res = new ArrayList<>();
    dfs(a, 0, new ArrayList<>(), res);
    return res;
}
private static void dfs(int[] a, int i, List<Integer> cur, List<List<Integer>> res) {
    if (i == a.length) { res.add(new ArrayList<>(cur)); return; }
    dfs(a, i + 1, cur, res);                               // без a[i]
    cur.add(a[i]);
    dfs(a, i + 1, cur, res);                               // с a[i]
    cur.remove(cur.size() - 1);
}
```
O(2^n). Битовый вариант: перебор масок 0..2^n−1 — сказать как альтернатива.

<a id="r6-t3"></a>
**3. [Классика] Combination Sum: набор монет, дающий сумму (повторения разрешены).**
```java
static List<List<Integer>> combinationSum(int[] candidates, int target) {
    List<List<Integer>> res = new ArrayList<>();
    Arrays.sort(candidates);
    cs(candidates, 0, target, new ArrayList<>(), res);
    return res;
}
private static void cs(int[] cand, int start, int target, List<Integer> cur, List<List<Integer>> res) {
    if (target == 0) { res.add(new ArrayList<>(cur)); return; }
    for (int i = start; i < cand.length; i++) {
        if (cand[i] > target) break;                    // отсортированы — дальше только больше
        cur.add(cand[i]);
        cs(cand, i, target - cand[i], cur, res);        // i, а не i+1: элемент можно брать повторно
        cur.remove(cur.size() - 1);
    }
}
```
`start` отсекает дубликатные комбинации — «2,2,3» и «2,3,2» не обе.

<a id="r6-t4"></a>
**4. [Классика] Буквы телефонного калькулятора.**
```java
private static final String[] KEYS = {"", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};

static List<String> keypad(String digits) {
    List<String> res = new ArrayList<>();
    if (!digits.isEmpty()) backtrack(digits, 0, new StringBuilder(), res);
    return res;
}
private static void backtrack(String d, int i, StringBuilder sb, List<String> res) {
    if (i == d.length()) { res.add(sb.toString()); return; }
    for (char c : KEYS[d.charAt(i) - '0'].toCharArray()) {
        sb.append(c);
        backtrack(d, i + 1, sb, res);
        sb.deleteCharAt(sb.length() - 1);
    }
}
```
O(4^n). StringBuilder переиспользуется — append/delete на каждом шаге.

<a id="r6-t5"></a>
**5. [Классика] Сгенерировать все корректные скобочные последовательности.**
```java
static List<String> generateParentheses(int n) {
    List<String> res = new ArrayList<>();
    gen(n, n, new StringBuilder(), res);
    return res;
}
private static void gen(int open, int close, StringBuilder sb, List<String> res) {
    if (open == 0 && close == 0) { res.add(sb.toString()); return; }
    if (open > 0)     { sb.append('('); gen(open - 1, close, sb, res); sb.deleteCharAt(sb.length() - 1); }
    if (close > open) { sb.append(')'); gen(open, close - 1, sb, res); sb.deleteCharAt(sb.length() - 1); }
}
```
Инварианты: открывающих осталось ≥ 0; закрывающую ставим только если уже есть незакрытая открывающая (`close > open`). Число Каталана.

<a id="r6-t6"></a>
**6. [Классика] Развернуть произвольно вложенный список.**
```java
static void flatten(List<Object> nested, List<Integer> out) {
    for (Object o : nested) {
        if (o instanceof List<?> inner) flatten((List<Object>) inner, out);  // Java 16+ pattern matching
        else out.add((Integer) o);
    }
}
```
Фоллоу-ап: та же задача итеративно через явный стек `Deque<Iterator<?>>` — частый вопрос на middle, уметь набросать.

<a id="r6-t7"></a>
**7. [Классика] Рекурсивный реверс строки и разговор о TCO.**
```java
static String reverse(String s) {
    return s.isEmpty() ? s : reverse(s.substring(1)) + s.charAt(0);
}
```
O(n²) по времени (конкатенация) и O(n²) памяти; глубина стека O(n), на строке в миллионы символов — StackOverflowError. В Java НЕТ оптимизации хвостовой рекурсии — итеративный вариант со StringBuilder обязателен. Любят спрашивать «чем плох этот красивый однострочник».

<a id="r6-t8"></a>
**8. [Классика] Ханойские башни.**
```java
static void hanoi(int n, char from, char to, char via, List<String> moves) {
    if (n == 0) return;
    hanoi(n - 1, from, via, to, moves);
    moves.add(from + " -> " + to);
    hanoi(n - 1, via, to, from, moves);
}
// число перемещений: 2^n - 1
```
Классика объяснения рекурсии: «снимаем n−1 на запасную, перекладываем нижний, возвращаем n−1 сверху».

## Раздел 7. Динамическое программирование
> Что проверяют: переход от рекурсии к таблице, сжатие состояний до одномерного массива, направление обхода.

<a id="r7-t1"></a>
**1. [Классика] Лестница из n ступеней шагами 1 или 2.**
```java
static int stairs(int n) {
    int a = 1, b = 1;                       // f(0)=1, f(1)=1
    for (int i = 2; i <= n; i++) {
        int c = a + b;
        a = b; b = c;
    }
    return b;
}
```
O(n)/O(1). Ходовой вопрос: почему O(2^n) наивная рекурсия плоха (пересчёт), и что f(n) — числа Фибоначчи; для больших n — длинная арифметика или быстрое возведение матрицы.

<a id="r7-t2"></a>
**2. [Классика] Минимальное число монет для суммы.**
```java
static int minCoins(int[] coins, int amount) {
    final int INF = amount + 1;
    int[] dp = new int[amount + 1];         // dp[x] = мин. монет для суммы x
    Arrays.fill(dp, INF);
    dp[0] = 0;
    for (int x = 1; x <= amount; x++)
        for (int c : coins)
            if (c <= x) dp[x] = Math.min(dp[x], dp[x - c] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
}
```
O(amount·coins). `INF = amount+1` — корректный «недостижимо», не нужен Integer.MAX_VALUE (и +1 не переполнится).

<a id="r7-t3"></a>
**3. [Классика|hard] Наибольшая возрастающая подпоследовательность за O(n log n).**
```java
static int lis(int[] a) {
    List<Integer> tails = new ArrayList<>();  // tails[i] = мин. возможный хвост НВП длины i+1
    for (int x : a) {
        int lo = 0, hi = tails.size();
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (tails.get(mid) < x) lo = mid + 1; else hi = mid;   // lower bound
        }
        if (lo == tails.size()) tails.add(x); else tails.set(lo, x);
    }
    return tails.size();
}
```
База для объяснения: O(n²) — `dp[i] = max(dp[j]+1)` для всех j<i, a[i]>a[j]; затем факт о «хвостах» и бинарный поиск. `tails` — НЕ сама подпоследовательность, только её длины.

<a id="r7-t4"></a>
**4. [Классика] Наибольшая общая подпоследовательность.**
```java
static int lcs(String s, String t) {
    int[][] dp = new int[s.length() + 1][t.length() + 1];
    for (int i = 1; i <= s.length(); i++)
        for (int j = 1; j <= t.length(); j++)
            dp[i][j] = s.charAt(i - 1) == t.charAt(j - 1)
                ? dp[i - 1][j - 1] + 1
                : Math.max(dp[i - 1][j], dp[i][j - 1]);
    return dp[s.length()][t.length()];
}
```
O(n·m). Фоллоу-ап: восстановить саму НОП — идти по таблице назад от `dp[n][m]`.

<a id="r7-t5"></a>
**5. [Классика] Расстояние редактирования (Левенштейна).**
```java
static int editDistance(String s, String t) {
    int[][] dp = new int[s.length() + 1][t.length() + 1];
    for (int i = 0; i <= s.length(); i++) dp[i][0] = i;     // i удалений
    for (int j = 0; j <= t.length(); j++) dp[0][j] = j;     // j вставок
    for (int i = 1; i <= s.length(); i++)
        for (int j = 1; j <= t.length(); j++) {
            int cost = s.charAt(i - 1) == t.charAt(j - 1) ? 0 : 1;
            dp[i][j] = Math.min(dp[i - 1][j - 1] + cost,      // замена/совпадение
                       Math.min(dp[i - 1][j] + 1,             // удаление из s
                                dp[i][j - 1] + 1));           // вставка в s
        }
    return dp[s.length()][t.length()];
}
```
O(n·m). Практическое применение: diff, автодополнение, fuzzy-поиск — интервьюеры любят спросить «где это используется».

<a id="r7-t6"></a>
**6. [Классика] Максимум суммы без соседних элементов.**
```java
static int rob(int[] a) {
    int prev2 = 0, prev1 = 0;
    for (int x : a) {
        int cur = Math.max(prev1, prev2 + x);   // берём x (тогда соседа нельзя) или не берём
        prev2 = prev1; prev1 = cur;
    }
    return prev1;
}
```
O(n)/O(1). Фоллоу-ап: дома по кругу (первый и последний соседствуют) — два прогона: без первого и без последнего, берём max.

<a id="r7-t7"></a>
**7. [Классика] Уникальные пути в сетке m×n (только вправо/вниз).**
```java
static int uniquePaths(int m, int n) {
    int[] dp = new int[n];
    Arrays.fill(dp, 1);                       // первая строка — один путь
    for (int i = 1; i < m; i++)
        for (int j = 1; j < n; j++)
            dp[j] += dp[j - 1];               // сверху + слева
    return dp[n - 1];
}
```
O(m·n), память O(n). Комбинаторная альтернатива: C(m+n−2, m−1) — сказать.

<a id="r7-t8"></a>
**8. [Классика] Самый длинный палиндром-подстрока.**
```java
static String longestPalindrome(String s) {
    int[] best = {0, 0};                      // [lo, hi) лучшего ответа
    for (int i = 0; i < s.length(); i++) {
        expand(s, i, i, best);                // нечётная длина
        expand(s, i, i + 1, best);            // чётная длина
    }
    return s.substring(best[0], best[1]);
}
private static void expand(String s, int l, int r, int[] best) {
    while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) { l--; r++; }
    l++; r--;
    if (r - l + 1 > best[1] - best[0]) { best[0] = l; best[1] = r + 1; }
}
```
O(n²) время, O(1) память — расширение от центра. ДП-таблица тоже O(n²)/O(n²) — уметь нарисовать оба и сказать, что Manacher даёт O(n), но его не спрашивают писать.

<a id="r7-t9"></a>
**9. [Классика] Word Break: разбивается ли строка на слова словаря.**
```java
static boolean wordBreak(String s, List<String> dict) {
    Set<String> words = new HashSet<>(dict);
    boolean[] can = new boolean[s.length() + 1];   // can[i] = разбивается ли префикс длины i
    can[0] = true;
    for (int i = 1; i <= s.length(); i++)
        for (int j = 0; j < i; j++)
            if (can[j] && words.contains(s.substring(j, i))) { can[i] = true; break; }
    return can[s.length()];
}
```
O(n²) с хеш-поиском. Улучшение: перебирать только длины слов словаря; для полного разбора — backtracking с мемоизацией.

<a id="r7-t10"></a>
**10. [Классика|hard] Разбить ли массив на два равных по сумме подмножества.**
0/1-рюкзак по булевой таблице.
```java
static boolean canPartition(int[] a) {
    int sum = Arrays.stream(a).sum();
    if (sum % 2 != 0) return false;
    int target = sum / 2;
    boolean[] dp = new boolean[target + 1];      // dp[s] = набирается ли сумма s
    dp[0] = true;
    for (int x : a)
        for (int s = target; s >= x; s--)        // ОБРАТНЫЙ порядок: каждый предмет один раз
            dp[s] |= dp[s - x];
    return dp[target];
}
```
O(n·sum). Прямой порядок — ошибка: предмет попадёт в набор несколько раз (станет полным рюкзаком). Различие направлений обхода — топ-вопрос.

## Раздел 8. Связные списки
> Что проверяют: перелинковка указателей без потери узлов, fixed-узор «фиктивная голова», slow/fast.

Вспомогательный тип для всех задач:
```java
class ListNode { int val; ListNode next; ListNode(int val) { this.val = val; } }
```

<a id="r8-t1"></a>
**1. [Классика] Развернуть список. Итеративно и рекурсивно.**
```java
static ListNode reverse(ListNode head) {
    ListNode prev = null;
    while (head != null) {
        ListNode next = head.next;   // запомнили хвост
        head.next = prev;            // развернули ссылку
        prev = head;                 // сдвинули prev
        head = next;                 // сдвинули head
    }
    return prev;
}
static ListNode reverseRec(ListNode head) {
    if (head == null || head.next == null) return head;
    ListNode newHead = reverseRec(head.next);
    head.next.next = head;
    head.next = null;
    return newHead;
}
```
O(n). Рекурсивная версия — O(n) стека: уметь объяснить переприсваивание `head.next.next = head` на рисунке из 3 узлов.

<a id="r8-t2"></a>
**2. [Классика|hard] Цикл: обнаружить и найти его начало.**
```java
static ListNode cycleStart(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) {              // встретились внутри цикла
            slow = head;
            while (slow != fast) { slow = slow.next; fast = fast.next; }
            return slow;                 // вход в цикл
        }
    }
    return null;                         // цикла нет
}
```
Флойд. Объяснение второй фазы: пусть до входа в цикл d, цикл длины c; на встрече slow прошёл d + k, fast — d + k + m·c, и 2(d+k) = d+k+m·c → d + k ≡ 0 (mod c). Значит, от головы и от точки встречи до входа — одинаковое число шагов.

<a id="r8-t3"></a>
**3. [Классика] Середина списка.**
```java
static ListNode middle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }
    return slow;   // чётная длина — второй из двух средних
}
```
Один проход. Фоллоу-ап: вернуть первый из средних — условие `fast.next != null && fast.next.next != null`.

<a id="r8-t4"></a>
**4. [Классика] Слить два отсортированных списка.**
```java
static ListNode merge(ListNode a, ListNode b) {
    ListNode dummy = new ListNode(0), tail = dummy;
    while (a != null && b != null) {
        if (a.val <= b.val) { tail.next = a; a = a.next; }
        else                { tail.next = b; b = b.next; }
        tail = tail.next;
    }
    tail.next = (a != null) ? a : b;    // прицепили остаток
    return dummy.next;
}
```
Фиктивная голова (dummy) избавляет от if на первом элементе — проговорить этот приём явно.

<a id="r8-t5"></a>
**5. [Классика] Удалить n-й узел с конца за один проход.**
```java
static ListNode removeNth(ListNode head, int n) {
    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode fast = dummy, slow = dummy;
    for (int i = 0; i <= n; i++) fast = fast.next;   // разрыв n между slow и fast
    while (fast != null) { fast = fast.next; slow = slow.next; }
    slow.next = slow.next.next;
    return dummy.next;
}
```
dummy обязателен: удаляемый может быть головой (n = длина).

<a id="r8-t6"></a>
**6. [Классика] Палиндром-список за O(n) время / O(1) памяти.**
```java
static boolean isPalindrome(ListNode head) {
    ListNode mid = middle(head);
    ListNode second = reverse(mid);      // развернули вторую половину
    ListNode p1 = head, p2 = second;
    boolean ok = true;
    while (p2 != null) {
        if (p1.val != p2.val) { ok = false; break; }
        p1 = p1.next; p2 = p2.next;
    }
    return ok;   // по желанию восстановить: middle-узел.next = reverse(second)
}
```
Три шага: середина → реверс половины → сравнение. Не забыть: интеграция «восстановить список» — вежливый ответ на фоллоу-ап.

<a id="r8-t7"></a>
**7. [Классика] Сложить два числа, заданных списками в обратном порядке.**
`(2→4→3) + (5→6→4)` = `7→0→8` (342 + 465 = 807).
```java
static ListNode add(ListNode a, ListNode b) {
    ListNode dummy = new ListNode(0), tail = dummy;
    int carry = 0;
    while (a != null || b != null || carry != 0) {
        int sum = carry;
        if (a != null) { sum += a.val; a = a.next; }
        if (b != null) { sum += b.val; b = b.next; }
        tail.next = new ListNode(sum % 10);
        tail = tail.next;
        carry = sum / 10;
    }
    return dummy.next;
}
```
Условие цикла с `carry != 0` обрабатывает появление нового разряда (999 + 1).

<a id="r8-t8"></a>
**8. [Классика|hard] Копия списка с random-указателем.**
```java
class RNode { int val; RNode next, random; }

static RNode copy(RNode head) {
    Map<RNode, RNode> map = new HashMap<>();       // старый узел -> его копия
    for (RNode p = head; p != null; p = p.next)
        map.put(p, new RNode(p.val));
    for (RNode p = head; p != null; p = p.next) {
        RNode c = map.get(p);
        c.next = map.get(p.next);       // map.get(null) == null — корректно
        c.random = map.get(p.random);
    }
    return map.get(head);
}
```
O(n)/O(n). Фоллоу-ап: O(1) памяти — трюк с вплетением копий `A→A'→B→B'...` с последующим разъединением; уметь описать словами.

## Раздел 9. Стеки, очереди, деки
> Что проверяют: инвариант «монотонный стек», амортизированные структуры, дек как окно.

<a id="r9-t1"></a>
**1. [Классика] Корректность скобочной последовательности.**
```java
static boolean valid(String s) {
    Deque<Character> st = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        switch (c) {
            case '(', '[', '{' -> st.push(c);
            case ')' -> { if (st.isEmpty() || st.pop() != '(') return false; }
            case ']' -> { if (st.isEmpty() || st.pop() != '[') return false; }
            case '}' -> { if (st.isEmpty() || st.pop() != '{') return false; }
            default -> { }
        }
    }
    return st.isEmpty();          // остались незакрытые — false
}
```
O(n). Любимая ошибка: забыть финальную проверку `isEmpty` для случая `"(("`.

<a id="r9-t2"></a>
**2. [Дизайн] Стек с минимумом за O(1).**
```java
class MinStack {
    private final Deque<Integer> values = new ArrayDeque<>();
    private final Deque<Integer> mins = new ArrayDeque<>();     // параллельный стек минимумов
    public void push(int v) {
        values.push(v);
        mins.push(mins.isEmpty() || v < mins.peek() ? v : mins.peek());
    }
    public int pop()     { mins.pop(); return values.pop(); }
    public int peek()    { return values.peek(); }
    public int min()     { return mins.peek(); }
}
```
O(1) на все операции. Одностековые трюки с кодированием разницы — упомянуть, но параллельный стек — чистое решение.

<a id="r9-t3"></a>
**3. [Классика] Обратная польская запись.**
```java
static int rpn(String[] tokens) {
    Deque<Integer> st = new ArrayDeque<>();
    for (String t : tokens) {
        switch (t) {
            case "+" -> st.push(st.pop() + st.pop());
            case "*" -> st.push(st.pop() * st.pop());
            case "-" -> { int b = st.pop(), a = st.pop(); st.push(a - b); }   // порядок!
            case "/" -> { int b = st.pop(), a = st.pop(); st.push(a / b); }
            default  -> st.push(Integer.parseInt(t));
        }
    }
    return st.pop();
}
```
Порядок операндов для «−» и «/» — главный источник бага. Отрицательные числа парсятся `parseInt` нормально — проговорить.

<a id="r9-t4"></a>
**4. [Классика] Следующий больший элемент для каждого.**
```java
static int[] nextGreater(int[] a) {
    int[] res = new int[a.length];
    Arrays.fill(res, -1);
    Deque<Integer> st = new ArrayDeque<>();        // индексы; значения в стеке убывают
    for (int i = 0; i < a.length; i++) {
        while (!st.isEmpty() && a[st.peek()] < a[i])
            res[st.pop()] = a[i];                  // a[i] — «следующий больший» для них
        st.push(i);
    }
    return res;
}
```
Монотонный стек: каждый индекс кладётся и вынимается один раз — O(n), несмотря на вложенный while. Уметь доказать амортизированную оценку.

<a id="r9-t5"></a>
**5. [С_нуля] Очередь на двух стеках.**
```java
class MyQueue<T> {
    private final Deque<T> in = new ArrayDeque<>();
    private final Deque<T> out = new ArrayDeque<>();
    public void offer(T v) { in.push(v); }
    public T poll() { peek(); return out.pop(); }
    public T peek() {
        if (out.isEmpty())                        // перекладываем лениво, один раз на элемент
            while (!in.isEmpty()) out.push(in.pop());
        return out.peek();
    }
    public boolean isEmpty() { return in.isEmpty() && out.isEmpty(); }
}
```
Амортизированно O(1): каждый элемент перекладывается ровно один раз. Классический вопрос про амортизацию.

<a id="r9-t6"></a>
**6. [Классика|hard] Максимумы всех окон длины k.**
```java
static int[] windowMax(int[] a, int k) {
    int[] res = new int[a.length - k + 1];
    Deque<Integer> dq = new ArrayDeque<>();       // индексы; значения убывают; максимум — в голове
    for (int i = 0; i < a.length; i++) {
        if (!dq.isEmpty() && dq.peekFirst() <= i - k) dq.pollFirst();     // протухший индекс
        while (!dq.isEmpty() && a[dq.peekLast()] <= a[i]) dq.pollLast();  // бесполезные кандидаты
        dq.offerLast(i);
        if (i >= k - 1) res[i - k + 1] = a[dq.peekFirst()];
    }
    return res;
}
```
O(n) — дек с убывающими значениями. Наив «окно × пересчёт» — O(n·k), интервьюер обязательно спросит «а быстрее?».

<a id="r9-t7"></a>
**7. [Дизайн] История браузера: back/forward.**
```java
class BrowserHistory {
    private final Deque<String> back = new ArrayDeque<>();
    private final Deque<String> forward = new ArrayDeque<>();
    private String current;
    public BrowserHistory(String home) { current = home; }
    public void visit(String url)  { back.push(current); current = url; forward.clear(); }
    public String back()     { if (back.isEmpty()) return current; forward.push(current); return current = back.pop(); }
    public String forward()  { if (forward.isEmpty()) return current; back.push(current); return current = forward.pop(); }
}
```
Два стека, `forward.clear()` при новом переходе. Спросить про лимит памяти — «предефайненный maxSize с вытеснением».

<a id="r9-t8"></a>
**8. [Классика] Сколько дней до потепления.**
```java
static int[] dailyTemperatures(int[] t) {
    int[] res = new int[t.length];
    Deque<Integer> st = new ArrayDeque<>();       // индексы «ещё не дождавшихся»
    for (int i = 0; i < t.length; i++) {
        while (!st.isEmpty() && t[st.peek()] < t[i]) {
            int j = st.pop();
            res[j] = i - j;
        }
        st.push(i);
    }
    return res;
}
```
Монотонный стек «ожидающих». Остаток в стеке — дни без потепления (0 по умолчанию).

## Раздел 10. Деревья и BST
> Что проверяют: рекурсия с инвариантами, обходы без рекурсии, границы значений для BST.

Вспомогательный тип:
```java
class TreeNode { int val; TreeNode left, right; TreeNode(int val) { this.val = val; } }
```

<a id="r10-t1"></a>
**1. [Классика] Все обходы: рекурсивно и итеративно.**
```java
static void preOrder(TreeNode n) {                 // корень, лево, право
    if (n == null) return;
    System.out.print(n.val + " ");
    preOrder(n.left);
    preOrder(n.right);
}
static void inOrder(TreeNode n) {                  // лево, корень, право — отсортированно для BST
    if (n == null) return;
    inOrder(n.left);
    System.out.print(n.val + " ");
    inOrder(n.right);
}
static void preOrderIter(TreeNode root) {
    Deque<TreeNode> st = new ArrayDeque<>();
    if (root != null) st.push(root);
    while (!st.isEmpty()) {
        TreeNode n = st.pop();
        System.out.print(n.val + " ");
        if (n.right != null) st.push(n.right);     // правого кладём первым — выйдет вторым
        if (n.left  != null) st.push(n.left);
    }
}
static void inOrderIter(TreeNode root) {
    Deque<TreeNode> st = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !st.isEmpty()) {
        while (cur != null) { st.push(cur); cur = cur.left; }   // до упора влево
        cur = st.pop();
        System.out.print(cur.val + " ");
        cur = cur.right;
    }
}
static List<Integer> postOrder(TreeNode root) {    // обратный к «корень, право, лево»
    LinkedList<Integer> res = new LinkedList<>();
    Deque<TreeNode> st = new ArrayDeque<>();
    if (root != null) st.push(root);
    while (!st.isEmpty()) {
        TreeNode n = st.pop();
        res.addFirst(n.val);                       // prepend — разворачивает порядок
        if (n.left  != null) st.push(n.left);
        if (n.right != null) st.push(n.right);
    }
    return res;
}
```
Итеративный inorder — спрашивают чаще всего: «спускаемся влево, пока можем; достаём из стека; идём вправо».

**2. [Классика] Глубина дерева.**
```java
static int depth(TreeNode n) {
    return n == null ? 0 : 1 + Math.max(depth(n.left), depth(n.right));
}
```
O(n). Фоллоу-ап: минимальная глубина — не симметричная формула! Учесть узел с одним ребёнком: `if (n.left == null) return minDepth(n.right) + 1;` и наоборот.

**3. [Классика] Отразить дерево.**

```java
static TreeNode invert(TreeNode n) {
```

O(n). Проверка на понимание: результат обходов после инверта (preorder остаётся зеркальным).

**4. [Классика] Симметрично ли дерево.**
```java
static boolean symmetric(TreeNode root) { return mirror(root.left, root.right); }
private static boolean mirror(TreeNode a, TreeNode b) {
    if (a == null || b == null) return a == b;
    return a.val == b.val && mirror(a.left, b.right) && mirror(a.right, b.left);
}
```
Сравнение перекрёстно: `a.left ↔ b.right`. Не путать с «два одинаковых дерева» (`a.left↔b.left`).

<a id="r10-t5"></a>
**5. [Классика] Проверить корректность BST.**
```java
static boolean validBST(TreeNode n) { return valid(n, Long.MIN_VALUE, Long.MAX_VALUE); }
private static boolean valid(TreeNode n, long lo, long hi) {
    if (n == null) return true;
    if (n.val <= lo || n.val >= hi) return false;        // строгое неравенство: дубликаты запрещены
    return valid(n.left, lo, n.val) && valid(n.right, n.val, hi);
}
```
Частая ошибка: проверять только «левый меньше родителя» — ломается на внуках (пример: 5 → правый 7 → левый 6 у семёрки). Границы в long — от int-экстремумов. Альтернатива: inorder-обход должен быть строго возрастающим.

**6. [Классика] Общий предок: в бинарном дереве и в BST.**
```java
static TreeNode lca(TreeNode root, TreeNode a, TreeNode b) {   // общее дерево
    if (root == null || root == a || root == b) return root;
    TreeNode left = lca(root.left, a, b), right = lca(root.right, a, b);
    if (left != null && right != null) return root;   // развилка — это и есть предок
    return (left != null) ? left : right;
}
static TreeNode lcaBst(TreeNode root, TreeNode a, TreeNode b) { // BST: спуск по значениям
    while (root != null) {
        if (a.val < root.val && b.val < root.val)      root = root.left;
        else if (a.val > root.val && b.val > root.val) root = root.right;
        else return root;
    }
    return null;
}
```
BST-вариант O(h) без обхода. Проговорить: узел считается предком самого себя.

<a id="r10-t7"></a>
**7. [Классика] Обход по уровням списками.**
```java
static List<List<Integer>> levels(TreeNode root) {
    List<List<Integer>> res = new ArrayList<>();
    if (root == null) return res;
    Queue<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        int size = q.size();                    // фиксируем размер УРОВНЯ до начала выборки
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < size; i++) {
            TreeNode n = q.poll();
            level.add(n.val);
            if (n.left  != null) q.offer(n.left);
            if (n.right != null) q.offer(n.right);
        }
        res.add(level);
    }
    return res;
}
```
Паттерн «size-снимок» — базовый для всех BFS-по-уровням. Змейка (zigzag) — тот же BFS + `Collections.reverse` на нечётных уровнях.

**8. [Классика] Есть ли путь от корня к листу с заданной суммой.**
```java
static boolean hasPathSum(TreeNode n, int target) {
    if (n == null) return false;
    if (n.left == null && n.right == null) return target == n.val;   // лист
    return hasPathSum(n.left, target - n.val) || hasPathSum(n.right, target - n.val);
}
```
Определять лист строго как «оба ребёнка null». Фоллоу-ап: собрать все пути (backtracking с общим списком).

**9. [Классика|hard] Сериализация/десериализация дерева.**

**10. [Классика] K-й наименьший элемент BST.**
```java
static int kthSmallest(TreeNode root, int k) {
```

## Раздел 11. Кучи, top-K и потоковые выборки
> Что проверяют: PriorityQueue как «максимум из потока», инвариант кучи размера k, выбор мин-кучи или макс-кучи.

<a id="r11-t1"></a>
**1. [Дизайн] K-й по величине в потоке добавлений.**
```java
class KthLargest {
    private final PriorityQueue<Integer> min = new PriorityQueue<>();  // мин-куча — корень = k-й максимум
    private final int k;
    public KthLargest(int k, int[] init) {
        this.k = k;
        for (int x : init) add(x);
    }
    public int add(int x) {
        min.offer(x);
        if (min.size() > k) min.poll();      // вытесняем меньших
        return min.peek();
    }
}
```
O(log k) на добавление. Почему мин-куча для «k-й максимум» — вопрос-фильтр: корень мин-кучи размера k и есть k-й по величине.

<a id="r11-t2"></a>
**2. [Классика] Слить k отсортированных списков.**
```java
static ListNode mergeK(ListNode[] lists) {
    PriorityQueue<ListNode> pq = new PriorityQueue<>(Comparator.comparingInt(n -> n.val));
    for (ListNode h : lists) if (h != null) pq.offer(h);   // по голове каждого списка
    ListNode dummy = new ListNode(0), tail = dummy;
    while (!pq.isEmpty()) {
        ListNode n = pq.poll();              // минимальная голова
        tail.next = n;
        tail = n;
        if (n.next != null) pq.offer(n.next);
    }
    return dummy.next;
}
```
O(N log k), N — суммарное число узлов. Альтернатива — попарное слияние «внахлёст», O(N log k) тоже, но хуже по константе.

<a id="r11-t3"></a>
**3. [Классика] K ближайших точек к началу координат.**
```java
static int[][] kClosest(int[][] points, int k) {
    PriorityQueue<int[]> max = new PriorityQueue<>((p, q) -> Long.compare(dist2(q), dist2(p))); // макс-куча!
    for (int[] p : points) {
        max.offer(p);
        if (max.size() > k) max.poll();
    }
    return max.toArray(new int[0][]);
}
static long dist2(int[] p) { return (long) p[0] * p[0] + (long) p[1] * p[1]; }
```
Дистанцию считаем без sqrt — она монотонна. Переполнение при больших координатах исключаем умножениями в long.

<a id="r11-t4"></a>
**4. [Классика|hard] Task Scheduler: минимум слотов при охлаждении n.**
```java
static int leastInterval(char[] tasks, int n) {
    int[] f = new int[26];
    for (char t : tasks) f[t - 'A']++;
    int maxFreq = 0, maxCount = 0;
    for (int x : f) {
        if (x > maxFreq) { maxFreq = x; maxCount = 1; }
        else if (x == maxFreq) maxCount++;
    }
    // каркас из самой частой задачи: (maxFreq-1) блоков по (n+1) + хвост из maxCount штук
    return Math.max(tasks.length, (maxFreq - 1) * (n + 1) + maxCount);
}
```
Формула + объяснение: длина ограничена либо количеством задач, либо каркасом самой частой. Уметь на примере A,A,A,B,B,B,n=2 показать 8.

<a id="r11-t5"></a>
**5. [Классика|hard] Медиана потока чисел.**
```java
class MedianFinder {
    private final PriorityQueue<Integer> low  = new PriorityQueue<>(Comparator.reverseOrder()); // меньшая половина (макс-куча)
    private final PriorityQueue<Integer> high = new PriorityQueue<>();                          // большая половина (мин-куча)

    public void add(int x) {
        if (low.isEmpty() || x <= low.peek()) low.offer(x); else high.offer(x);
        if (low.size() > high.size() + 1) high.offer(low.poll());   // ребаланс: |size| <= 1
        else if (high.size() > low.size()) low.offer(high.poll());
    }
    public double median() {
        return low.size() > high.size() ? low.peek() : (low.peek() + high.peek()) / 2.0;
    }
}
```
O(log n) на добавление, O(1) медиана. Инвариант: всё в low ≤ всё в high, размеры отличаются максимум на 1. Объяснить наизусть — топ-вопрос собесов.

<a id="r11-t6"></a>
**6. [Классика] Last Stone Weight.**
Берём два самых тяжёлых камня, разбиваем друг о друга.
```java
static int lastStone(int[] stones) {
    PriorityQueue<Integer> pq = new PriorityQueue<>(Comparator.reverseOrder());
    for (int s : stones) pq.offer(s);
    while (pq.size() > 1) {
        int y = pq.poll(), x = pq.poll();
        if (y != x) pq.offer(y - x);
    }
    return pq.isEmpty() ? 0 : pq.peek();
}
```
Моделирование на макс-куче, O(n log n). Простая задача «насколько вы знаете PriorityQueue».

## Раздел 12. Графы: BFS, DFS и топологическая сортировка
> Что проверяют: сетка-граф, очередь/стек, посещённость, многоисточниковый BFS, инварианты раскраски.

<a id="r12-t1"></a>
**1. [Классика] Число островов в сетке.**
```java
static int islands(char[][] g) {                 // '1' — земля, '0' — вода
    int count = 0;
    for (int i = 0; i < g.length; i++)
        for (int j = 0; j < g[0].length; j++)
            if (g[i][j] == '1') { count++; sink(g, i, j); }
    return count;
}
private static void sink(char[][] g, int i, int j) {
    if (i < 0 || j < 0 || i >= g.length || j >= g[0].length || g[i][j] != '1') return;
    g[i][j] = '0';                               // «утопили» — заодно отметка посещённости
    sink(g, i + 1, j); sink(g, i - 1, j); sink(g, i, j + 1); sink(g, i, j - 1);
}
```
O(V+M). Фоллоу-апы: диагонали тоже считаются связью — добавить направления; нельзя менять вход — `boolean[][] visited` или множество «i:j»; большая сетка — итеративный стек против StackOverflowError.

<a id="r12-t2"></a>
**2. [Классика] Копия графа.**
```java
class GNode { int val; List<GNode> neighbors; GNode(int v) { val = v; neighbors = new ArrayList<>(); } }

static GNode clone(GNode node) {
    if (node == null) return null;
    return dfs(node, new HashMap<>());
}
private static GNode dfs(GNode n, Map<GNode, GNode> copies) {
    if (copies.containsKey(n)) return copies.get(n);     // уже скопирован: циклы!
    GNode copy = new GNode(n.val);
    copies.put(n, copy);                                 // кладём ДО обхода соседей
    for (GNode nb : n.neighbors) copy.neighbors.add(dfs(nb, copies));
    return copy;
}
```
Помещать копию в map до рекурсии — иначе бесконечная рекурсия на цикле. Классика на понимание «visited в процессе».

<a id="r12-t3"></a>
**3. [Классика|hard] Можно ли закончить все курсы (топологическая сортировка, алгоритм Кана).**
`prerequisites[i] = {a, b}`: для курса a нужен курс b.
```java
static boolean canFinish(int numCourses, int[][] prerequisites) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
    int[] indeg = new int[numCourses];
    for (int[] p : prerequisites) { adj.get(p[1]).add(p[0]); indeg[p[0]]++; }
    Deque<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < numCourses; i++) if (indeg[i] == 0) q.offer(i);
    int seen = 0;
    while (!q.isEmpty()) {
        int c = q.poll();
        seen++;
        for (int next : adj.get(c))
            if (--indeg[next] == 0) q.offer(next);
    }
    return seen == numCourses;   // меньше — цикл, порядок невозможен
}
```
O(V+E). Фоллоу-ап: вернуть сам порядок (массив course'ов по мере poll); DFS-вариант с тремя цветами (белый/серый/чёрный, цикл = ребро в серый).

<a id="r12-t4"></a>
**4. [Классика|hard] Word Ladder: кратчайшая цепочка слов.**
hot → dot → dog → cog, меняя по одной букве.
```java
static int ladderLength(String begin, String end, List<String> words) {
    Set<String> dict = new HashSet<>(words);
    if (!dict.contains(end)) return 0;
    Map<String, List<String>> pattern = new HashMap<>();      // "*ot" -> [hot, dot, lot]
    for (String w : dict)
        for (int i = 0; i < w.length(); i++)
            pattern.computeIfAbsent(w.substring(0, i) + '*' + w.substring(i + 1),
                    x -> new ArrayList<>()).add(w);
    Set<String> visited = new HashSet<>();
    visited.add(begin);
    Deque<String> q = new ArrayDeque<>();
    q.offer(begin);
    int steps = 1;
    while (!q.isEmpty()) {
        int size = q.size();
        for (int s = 0; s < size; s++) {
            String cur = q.poll();
            if (cur.equals(end)) return steps;
            for (int i = 0; i < cur.length(); i++) {
                String key = cur.substring(0, i) + '*' + cur.substring(i + 1);
                for (String next : pattern.getOrDefault(key, List.of()))
                    if (visited.add(next)) q.offer(next);
            }
        }
        steps++;
    }
    return 0;
}
```
BFS = кратчайший путь в невзвешенном графе. Вместо генерации 26 букв на позицию — предпосчитанные wildcard-группы: O(N·L) вместо O(N·26·L). Уметь объяснить, почему BFS, а не DFS.

**5. [Классика] Двудольный ли граф (2-раскраска).**
```java
static boolean bipartite(int[][] adj) {          // adj[v] — соседи вершины v
    int[] color = new int[adj.length];           // 0 — не раскрашен, 1 / -1 — цвета
    for (int start = 0; start < adj.length; start++) {   // граф может быть несвязным!
        if (color[start] != 0) continue;
        color[start] = 1;
        Deque<Integer> q = new ArrayDeque<>();
        q.offer(start);
        while (!q.isEmpty()) {
            int v = q.poll();
            for (int nb : adj[v]) {
                if (color[nb] == 0) { color[nb] = -color[v]; q.offer(nb); }
                else if (color[nb] == color[v]) return false;   // ребро внутри цвета
            }
        }
    }
    return true;
}
```
Забыть внешний цикл по компонентам — самая частая ошибка.

<a id="r12-t6"></a>
**6. [Классика] Гниющие апельсины: минуты до полного распространения.**
```java
static int orangesRotting(int[][] g) {           // 0 пусто, 1 свежий, 2 гнилой
    Deque<int[]> q = new ArrayDeque<>();
    int fresh = 0;
    for (int i = 0; i < g.length; i++)
        for (int j = 0; j < g[0].length; j++) {
            if (g[i][j] == 2) q.offer(new int[]{i, j});     // ВСЕ источники сразу
            if (g[i][j] == 1) fresh++;
        }
    int minutes = 0;
    int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
    while (!q.isEmpty() && fresh > 0) {
        int size = q.size();
        for (int s = 0; s < size; s++) {
            int[] c = q.poll();
            for (int[] d : dirs) {
                int i = c[0] + d[0], j = c[1] + d[1];
                if (i >= 0 && j >= 0 && i < g.length && j < g[0].length && g[i][j] == 1) {
                    g[i][j] = 2;
                    fresh--;
                    q.offer(new int[]{i, j});
                }
            }
        }
        minutes++;
    }
    return fresh == 0 ? minutes : -1;
}
```
Многоисточниковый BFS с шагом «уровень = минута». Фоллоу-ап: почему начальные гнилые не добавляют минуту (счётчик инкрементится после волны — объяснить off-by-one).

<a id="r12-t7"></a>
**7. [Классика] Заливка области цветом.**
```java
static int[][] floodFill(int[][] img, int sr, int sc, int color) {
    int from = img[sr][sc];
    if (from == color) return img;               // без проверки — бесконечная рекурсия!
    fill(img, sr, sc, from, color);
    return img;
}
private static void fill(int[][] img, int i, int j, int from, int color) {
    if (i < 0 || j < 0 || i >= img.length || j >= img[0].length || img[i][j] != from) return;
    img[i][j] = color;
    fill(img, i + 1, j, from, color); fill(img, i - 1, j, from, color);
    fill(img, i, j + 1, from, color); fill(img, i, j - 1, from, color);
}
```
Проверка «from == color» — обязательный edge case, о нём спрашивают.

<a id="r12-t8"></a>
**8. [С_нуля] Union-Find (системы непересекающихся множеств).**
```java
class DSU {
    private final int[] parent, rank_;
    DSU(int n) {
        parent = new int[n];
        rank_ = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }
    int find(int x) {
        return parent[x] == x ? x : (parent[x] = find(parent[x]));   // сжатие пути
    }
    boolean union(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;              // уже вместе: ребро избыточно (цикл)
        if (rank_[a] < rank_[b]) { int t = a; a = b; b = t; }
        parent[b] = a;
        if (rank_[a] == rank_[b]) rank_[a]++;
        return true;
    }
}
// пример: число связных компонент = n - (число успешных union)
```
Почти O(1) амортизированно (обратная функция Аккермана). Применения: компоненты, циклы в неориентированном графе, Краскал. Фоллоу-ап: считать размер компоненты — массив sizes, обновляемый в union.

## Раздел 13. Интервалы и жадные алгоритмы
> Что проверяют: сортировка как подготовка жадности, инвариант «текущий конец», отличие от ДП.

<a id="r13-t1"></a>
**1. [Классика] Слить пересекающиеся интервалы.**
```java
static int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
    List<int[]> res = new ArrayList<>();
    for (int[] cur : intervals) {
        if (!res.isEmpty() && cur[0] <= res.get(res.size() - 1)[1])          // пересекается
            res.get(res.size() - 1)[1] = Math.max(res.get(res.size() - 1)[1], cur[1]);
        else res.add(cur);
    }
    return res.toArray(new int[0][]);
}
```
O(n log n). Сортировка по старту — после неё пересекающиеся интервалы соседствуют. `Math.max` по концу — вложенные интервалы.

<a id="r13-t2"></a>
**2. [Классика] Может ли человек посетить все встречи.**
```java
static boolean canAttendAll(int[][] meetings) {
    Arrays.sort(meetings, Comparator.comparingInt(a -> a[0]));
    for (int i = 1; i < meetings.length; i++)
        if (meetings[i][0] < meetings[i - 1][1]) return false;   // начало раньше прошлого конца
    return true;
}
```
O(n log n). Является ли «встреча начинается ровно в конце прошлой» пересечением — уточнить у интервьюера ([start, end) — нет).

<a id="r13-t3"></a>
**3. [Классика|hard] Минимальное число переговорных.**
```java
static int minRooms(int[][] meetings) {
    Arrays.sort(meetings, Comparator.comparingInt(a -> a[0]));
    PriorityQueue<Integer> ends = new PriorityQueue<>();   // времена окончания активных встреч
    for (int[] m : meetings) {
        if (!ends.isEmpty() && ends.peek() <= m[0]) ends.poll();   // комната освободилась — переиспользуем
        ends.offer(m[1]);
    }
    return ends.size();    // размер кучи в пике = число одновременно идущих встреч
}
```
O(n log n). Альтернатива — два отсортированных массива стартов/концов с двумя указателями; объяснить эквивалентность. Обязательно пройти пример, где комнаты переиспользуются.

<a id="r13-t4"></a>
**4. [Классика] Минимум интервалов к удалению, чтобы убрать пересечения.**
```java
static int eraseOverlap(int[][] intervals) {
    Arrays.sort(intervals, Comparator.comparingInt(a -> a[1]));   // по КОНЦУ
    int kept = 0, end = Integer.MIN_VALUE;
    for (int[] iv : intervals)
        if (iv[0] >= end) { kept++; end = iv[1]; }                // жадно берём заканчивающийся раньше
    return intervals.length - kept;
}
```
Жадность «минимальный конец» доказывается обменным аргументом — уметь пересказать: раньше заканчивающийся интервал не хуже любого другого для будущих.

<a id="r13-t5"></a>
**5. [Классика] Достижим ли последний индекс прыжками.**
```java
static boolean canJump(int[] a) {
    int reach = 0;
    for (int i = 0; i < a.length; i++) {
        if (i > reach) return false;             // в эту клетку не добраться
        reach = Math.max(reach, i + a[i]);
    }
    return true;
}
```
O(n)/O(1). Инвариант: `reach` — самая правая достижимая клетка. Фоллоу-ап: минимальное число прыжков — BFS-по-уровням на той же идее.

<a id="r13-t6"></a>
**6. [Классика|hard] Круговая маршрутка: с какой заправки стартовать.**
`gas[i]`/`cost[i]`, объезд по кругу.
```java
static int canCompleteCircuit(int[] gas, int[] cost) {
    int total = 0, tank = 0, start = 0;
    for (int i = 0; i < gas.length; i++) {
        int d = gas[i] - cost[i];
        total += d;
        tank += d;
        if (tank < 0) { start = i + 1; tank = 0; }   // с любого старта до i не доехать — стартуем после
    }
    return total >= 0 ? start : -1;
}
```
Два факта: суммарный дефицит ≥ 0 → решение существует; если из старта s до i не хватило — ни один старт внутри (s, i] не годится. O(n) один проход.

## Раздел 14. Collections Framework на практике

**1. [Дизайн] LRU-кэш через LinkedHashMap.**
```java
class LRUCache<K, V> extends LinkedHashMap<K, V> {

    LRUCache(int cap) {

    @Override
```

**7. [Классика] BitSet: недостающие числа из потока.**

```java
    for (int x : present) seen.set(x);
    List<Integer> res = new ArrayList<>();

    return res;
}
```
BitSet — один бит на число, в 32+ раза меньше памяти, чем `int[]`. Спросить про `nextClearBit` как ускорение подряд идущих дыр.

## Раздел 15. Структуры данных с нуля
> Что проверяют: понимание того, что внутри ArrayList/HashMap/кучи; амортизированные оценки; resize-стратегии.

<a id="r15-t1"></a>
**1. [С_нуля] Свой ArrayList.**
```java
class MyArrayList<T> {
    private Object[] data = new Object[8];
    private int size;
    public void add(T v) {
        if (size == data.length) data = Arrays.copyOf(data, data.length * 2);  // рост x2 — амортизация O(1)
        data[size++] = v;
    }
    @SuppressWarnings("unchecked")
    public T get(int i) {
        if (i < 0 || i >= size) throw new IndexOutOfBoundsException("index " + i);
        return (T) data[i];
    }
    public T remove(int i) {
        T v = get(i);
        System.arraycopy(data, i + 1, data, i, size - i - 1);   // сдвиг хвоста влево
        data[--size] = null;                                    // не держим ссылку — GC
        return v;
    }
    public int size() { return size; }
}
```
Обязательные пояснения: рост ×2 → амортизированное add; зануление слота при remove; ArrayList из JDK shrinking не делает (только trimToSize).

<a id="r15-t2"></a>
**2. [С_нуля|hard] Свой HashMap.**
```java
class MyHashMap<K, V> {
    private static final double LOAD = 0.75;
    private Node<K, V>[] buckets = new Node[8];
    private int size;

    private static class Node<K, V> {
        final K key; V value; Node<K, V> next;
        Node(K key, V value) { this.key = key; this.value = value; }
    }

    public V get(K key) {
        for (Node<K, V> n = buckets[index(key)]; n != null; n = n.next)
            if (n.key.equals(key)) return n.value;
        return null;
    }

    public void put(K key, V value) {
        int i = index(key);
        for (Node<K, V> n = buckets[i]; n != null; n = n.next)
            if (n.key.equals(key)) { n.value = value; return; }   // обновление существующего
        buckets[i] = new Node<>(key, value);                      // вставка в голову цепочки
        if (++size > buckets.length * LOAD) rehash();
    }

    private int index(K key) {   // «хеш-улучшение»: старшие биты участвуют в младших
        int h = key.hashCode();
        return (h ^ (h >>> 16)) & (buckets.length - 1);           // длина — степень двойки
    }

    @SuppressWarnings("unchecked")
    private void rehash() {
        Node<K, V>[] old = buckets;
        buckets = new Node[old.length * 2];
        size = 0;
        for (Node<K, V> head : old)
            for (Node<K, V> n = head; n != null; n = n.next)
                put(n.key, n.value);                              // переразмещение всех записей
    }

    public int size() { return size; }
}
```
Уметь рассказать: цепочки против открытой адресации; почему длина — степень двойки (`& (n-1)` вместо `%`); load factor и момент рехеша; null-ключи не поддержаны; JDK-версия с 8 превращает длинную цепочку в красно-чёрное дерево (O(log n) при плохих хешах).

<a id="r15-t3"></a>
**3. [С_нуля] Свой LinkedList с Iterable.**
```java
class MyLinkedList<T> implements Iterable<T> {
    private static class Node<T> { T val; Node<T> next; Node(T v) { val = v; } }
    private Node<T> head, tail;
    private int size;

    public void add(T v) {
        Node<T> n = new Node<>(v);
        if (head == null) head = tail = n;
        else { tail.next = n; tail = n; }
        size++;
    }
    public int size() { return size; }

    @Override
    public Iterator<T> iterator() {
        return new Iterator<>() {
            Node<T> cur = head;
            @Override public boolean hasNext() { return cur != null; }
            @Override public T next() {
                if (cur == null) throw new NoSuchElementException();
                T v = cur.val;
                cur = cur.next;
                return v;
            }
        };
    }
}
```
Реализация `Iterable<T>` включает for-each — проверка, что кандидат знает про итератор, а не только про узлы.

<a id="r15-t4"></a>
**4. [С_нуля] Кольцевой буфер (bounded queue).**
```java
class RingBuffer<T> {
    private final Object[] buf;
    private int head, size;
    RingBuffer(int cap) { buf = new Object[cap]; }

    public boolean offer(T v) {                 // false — буфер полон (или расти, или блокировать)
        if (size == buf.length) return false;
        buf[(head + size) % buf.length] = v;
        size++;
        return true;
    }
    @SuppressWarnings("unchecked")
    public T poll() {
        if (size == 0) throw new NoSuchElementException();
        T v = (T) buf[head];
        buf[head] = null;
        head = (head + 1) % buf.length;
        size--;
        return v;
    }
    public int size() { return size; }
}
```
`(head + size) % len` для записи и инкремент head для чтения — два способа обойти деление по модулю. База для понимания ArrayBlockingQueue.

<a id="r15-t5"></a>
**5. [С_нуля] Своя мин-куча.**
```java
class MinHeap {
    private int[] a = new int[8];
    private int size;

    public void add(int v) {
        if (size == a.length) a = Arrays.copyOf(a, a.length * 2);
        a[size] = v;
        int i = size++;
        while (i > 0 && a[i] < a[(i - 1) / 2]) { swap(i, (i - 1) / 2); i = (i - 1) / 2; }  // sift up
    }
    public int peek() {
        if (size == 0) throw new NoSuchElementException();
        return a[0];
    }
    public int poll() {
        int min = peek();
        a[0] = a[--size];
        siftDown(0);
        return min;
    }
    private void siftDown(int i) {
        while (true) {
            int l = 2 * i + 1, r = l + 1, m = i;
            if (l < size && a[l] < a[m]) m = l;
            if (r < size && a[r] < a[m]) m = r;
            if (m == i) return;
            swap(i, m);
            i = m;
        }
    }
    private void swap(int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
}
```
Родитель `(i-1)/2`, дети `2i+1`/`2i+2` — знать наизусть. add/poll — O(log n), peek — O(1). Фоллоу-ап: heapify массива за O(n) — снизу вверх siftDown.

<a id="r15-t6"></a>
**6. [С_нуля] Префиксное дерево (trie).**
```java
class Trie {
    private static class Node {
        Node[] next = new Node[26];
        boolean end;
    }
    private final Node root = new Node();

    public void add(String w) {
        Node n = root;
        for (char c : w.toCharArray()) {
            int i = c - 'a';
            if (n.next[i] == null) n.next[i] = new Node();
            n = n.next[i];
        }
        n.end = true;                       // помечаем конец слова
    }
    public boolean contains(String w)  { Node n = find(w); return n != null && n.end; }
    public boolean startsWith(String p) { return find(p) != null; }
    private Node find(String s) {
        Node n = root;
        for (char c : s.toCharArray()) {
            n = n.next[c - 'a'];
            if (n == null) return null;
        }
        return n;
    }
}
```
O(len) на операцию. Применения: автодополнение, словари, IP-маршрутизация. Фоллоу-ап: узел с `Map<Character, Node>` для произвольного алфавита; поиск по префиксу с обходом поддерева.

<a id="r15-t7"></a>
**7. [С_нуля|hard] LRU-кэш на HashMap + двусвязном списке.**
```java
class LRUCache<K, V> {
    private static class Node<K, V> {
        final K key; V value; Node<K, V> prev, next;
        Node(K key, V value) { this.key = key; this.value = value; }
    }
    private final Map<K, Node<K, V>> map = new HashMap<>();   // ключ -> узел
    private final Node<K, V> head = new Node<>(null, null);   // фиктивные границы
    private final Node<K, V> tail = new Node<>(null, null);
    private final int cap;

    public LRUCache(int cap) {
        this.cap = cap;
        head.next = tail;
        tail.prev = head;
    }

    public V get(K key) {
        Node<K, V> n = map.get(key);
        if (n == null) return null;
        unlink(n);
        pushFront(n);                       // любое обращение = «свежесть»
        return n.value;
    }

    public void put(K key, V value) {
        Node<K, V> n = map.get(key);
        if (n != null) { n.value = value; unlink(n); pushFront(n); return; }
        n = new Node<>(key, value);
        map.put(key, n);
        pushFront(n);
        if (map.size() > cap) {             // вытеснение хвостового (самого старого)
            Node<K, V> lru = tail.prev;
            unlink(lru);
            map.remove(lru.key);
        }
    }

    private void unlink(Node<K, V> n)       { n.prev.next = n.next; n.next.prev = n.prev; }
    private void pushFront(Node<K, V> n)    {
        n.next = head.next; n.prev = head;
        head.next.prev = n; head.next = n;
    }
}
```
O(1) на get/put. HashMap даёт доступ за O(1), список поддерживает порядок и вытеснение; узел хранит ключ — чтобы удалить из map при вытеснении. Фоллоу-апы: потокобезопасность (синхронизировать методы или шардировать); TTL поверх LRU.

<a id="r15-t8"></a>
**8. [С_нуля] Упрощённый Bloom-фильтр.**
```java
class SimpleBloomFilter {
    private final BitSet bits;
    private final int size;
    SimpleBloomFilter(int size) { this.size = size; this.bits = new BitSet(size); }

    public void add(String s) {
        for (int h : hashes(s)) bits.set(h % size);
    }
    public boolean mightContain(String s) {   // false — точно нет; true — возможно (ложные срабатывания)
        for (int h : hashes(s))
            if (!bits.get(h % size)) return false;
        return true;
    }
    private int[] hashes(String s) {          // разные множители — «разные» хеш-функции
        int h1 = s.hashCode(), h2 = s.hashCode() * 31 + 7;
        return new int[]{ h1 & 0x7fffffff, h2 & 0x7fffffff };  // без Math.abs: abs(MIN_VALUE) < 0!
    }
}
```
Объяснить: нет ложноотрицательных, есть ложнопозитивные; вероятность падает с ростом размера и числа хешей; удаления нет (сброс бита заденет другие элементы). Подводный камень `Math.abs(Integer.MIN_VALUE)` — вернуть минус — стоит проговорить, интервьюеры это любят.

## Раздел 16. Многопоточность и синхронизация
> Что проверяют: wait/notify против ReentrantLock/Condition, volatile/atomic, InterruptedException-этикет, дедлоки, выбор примитива под задачу. Самый «.middle» раздел: задачи дают почти всегда.

<a id="r16-t1"></a>
**1. [Потоки] Два потока печатают чёт/нечет по очереди (wait/notify).**
```java
class OddEvenPrinter {
    private final Object monitor = new Object();
    private volatile boolean oddTurn = true;
    private final int limit;
    OddEvenPrinter(int limit) { this.limit = limit; }

    public void printOdd() throws InterruptedException {
        for (int i = 1; i <= limit; i += 2) {
            synchronized (monitor) {
                while (!oddTurn) monitor.wait();     // while — защита от ложных пробуждений
                System.out.println("odd: " + i);
                oddTurn = false;
                monitor.notifyAll();
            }
        }
    }
    public void printEven() throws InterruptedException {
        for (int i = 2; i <= limit; i += 2) {
            synchronized (monitor) {
                while (oddTurn) monitor.wait();
                System.out.println("even: " + i);
                oddTurn = true;
                monitor.notifyAll();
            }
        }
    }
}
// запуск:
OddEvenPrinter p = new OddEvenPrinter(10);
new Thread(() -> runUnchecked(p::printOdd)).start();
new Thread(() -> runUnchecked(p::printEven)).start();
```
Три вещи, которые спрашивают: wait в while; wait/notify только внутри synchronized (иначе IllegalMonitorStateException); notifyAll против notify (notify может разбудить «не того»).

<a id="r16-t2"></a>
**2. [Потоки] То же через ReentrantLock + Condition.**
```java
class OddEvenLock {
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition oddTurn  = lock.newCondition();
    private final Condition evenTurn = lock.newCondition();
    private boolean isOdd = true;

    void print(int from, int step, int limit, boolean odd) throws InterruptedException {
        for (int i = from; i <= limit; i += step) {
            lock.lock();
            try {
                while (isOdd != odd)
                    (odd ? oddTurn : evenTurn).await();
                System.out.println(i);
                isOdd = !isOdd;
                (odd ? evenTurn : oddTurn).signal();     // будим конкретного «соседа»
            } finally {
                lock.unlock();
            }
        }
    }
}
```
Преимущества против wait/notify: отдельные условия (не будим лишних), lock с таймаутом/прерыванием, честность (fairness). unlock — строго в finally.

<a id="r16-t3"></a>
**3. [Потоки] Три потока печатают A/B/C строго по кругу N раз.**
```java
class ABCPrinter {
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition[] ready = {lock.newCondition(), lock.newCondition(), lock.newCondition()};
    private int turn = 0;   // чей ход

    void print(int id, int times) throws InterruptedException {   // id = 0,1,2
        for (int k = 0; k < times; k++) {
            lock.lock();
            try {
                while (turn != id) ready[id].await();
                System.out.print((char) ('A' + id));
                turn = (id + 1) % 3;
                ready[turn].signal();
            } finally {
                lock.unlock();
            }
        }
    }
}
```
Обобщение чёт/нечет на N участников. Фоллоу-ап: semaphore-вариант — три Semaphore(1,0,0), после печати release следующего.

<a id="r16-t4"></a>
**4. [Потоки|hard] Producer/Consumer на wait/notify: ограниченный буфер.**
```java
class BoundedBuffer<T> {
    private final Object[] buf;
    private int take, put, count;
    BoundedBuffer(int cap) { buf = new Object[cap]; }

    public synchronized void put(T v) throws InterruptedException {
        while (count == buf.length) wait();        // while, не if: после пробуждения могли заполнить
        buf[put] = v;
        if (++put == buf.length) put = 0;
        count++;
        notifyAll();
    }
    @SuppressWarnings("unchecked")
    public synchronized T take() throws InterruptedException {
        while (count == 0) wait();
        T v = (T) buf[take];
        buf[take] = null;                          // не держим ссылки
        if (++take == buf.length) take = 0;
        count--;
        notifyAll();
        return v;
    }
}
```
Каноничное решение из «Java Concurrency in Practice». Спросить: почему notifyAll (двустороннее ожидание — notify может разбудить однотипного); что будет с if вместо while (потерянные пробуждения/переполнение).

<a id="r16-t5"></a>
**5. [Потоки] Producer/Consumer на ArrayBlockingQueue.**
```java
BlockingQueue<Integer> q = new ArrayBlockingQueue<>(100);

Runnable producer = () -> {
    try {
        for (int i = 0; i < 1_000; i++) q.put(i);   // блокируется при заполнении
        q.put(-1);                                   // poison pill — сигнал конца
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
};
Runnable consumer = () -> {
    try {
        while (true) {
            int v = q.take();                        // блокируется при пустой очереди
            if (v == -1) { q.put(-1); break; }       // пропустить сигнал дальше — для остальных потребителей
            process(v);
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
};
```
put/take — блокирующие, offer/poll с таймаутом — неблокирующие. Poison pill — идиома завершения; фоллоу-ап: несколько продюсеров — счётчик завершившихся.

<a id="r16-t6"></a>
**6. [Потоки] Потокобезопасный счётчик: четыре способа и их цена.**
```java
// 1. synchronized — прост, но сериализует все потоки
class Counter1 { private long v; public synchronized void inc() { v++; } public synchronized long get() { return v; } }
// 2. AtomicLong — CAS-цикл, без блокировки: лучше при низкой конкуренции
class Counter2 { private final AtomicLong v = new AtomicLong(); public void inc() { v.incrementAndGet(); } public long get() { return v.get(); } }
// 3. LongAdder — суммирование по ячейкам: побеждает при ОЧЕНЬ высокой конкуренции
class Counter3 { private final LongAdder v = new LongAdder(); public void inc() { v.increment(); } public long get() { return v.sum(); } }
// 4. единственный поток-писатель + volatile — нет конкуренции на запись
class Counter4 { private volatile long v; public void inc() { v++; } public long get() { return v; } }   // ++ НЕ атомарен: годится ТОЛЬКО если пишет один поток
```
Объяснить: `v++` = чтение+инкремент+запись (check-then-act); volatile даёт видимость и happens-before, но не атомарность составных операций.

<a id="r16-t7"></a>
**7. [Потоки] Написать дедлок и починить.**
```java
final Object lock1 = new Object(), lock2 = new Object();

// ДЕДЛОК: каждый держит свой лок и ждёт чужой
new Thread(() -> {
    synchronized (lock1) { sleep(50); synchronized (lock2) { work(); } }
}).start();
new Thread(() -> {
    synchronized (lock2) { sleep(50); synchronized (lock1) { work(); } }
}).start();

// ФИКС 1 — единый глобальный порядок захвата (по id/по hash):
Object first = System.identityHashCode(lock1) <= System.identityHashCode(lock2) ? lock1 : lock2;

// ФИКС 2 — tryLock с таймаутом и откатом:
ReentrantLock l1 = new ReentrantLock(), l2 = new ReentrantLock();
if (l1.tryLock(1, TimeUnit.SECONDS)) {
    try {
        if (l2.tryLock(1, TimeUnit.SECONDS)) {
            try { work(); } finally { l2.unlock(); }
        }
    } finally { l1.unlock(); }
}
```
Диагностика: jstack / Thread.getStackTrace() — показывает «Found one Java-level deadlock». Проговорить: дедлок возможен только при вложенных захватах; минимальные критические секции снижают риск, но не устраняют его.

<a id="r16-t8"></a>
**8. [Потоки] Ленивый синглтон: три безопасных способа.**
```java
// 1. enum — кратко, защищено от рефлексии и сериализации (Effective Java)
enum Singleton1 { INSTANCE; public void doWork() { /* ... */ } }

// 2. holder — ленивость бесплатно: класс Holder инициализируется при первом обращении
class Singleton2 {
    private Singleton2() { }
    private static class Holder { static final Singleton2 INSTANCE = new Singleton2(); }
    public static Singleton2 instance() { return Holder.INSTANCE; }
}

// 3. double-checked locking — работает ТОЛЬКО с volatile
class Singleton3 {
    private static volatile Singleton3 instance;      // volatile запрещает переупорядочение создания
    private Singleton3() { }
    public static Singleton3 instance() {
        if (instance == null)                          // быстрый путь без локов
            synchronized (Singleton3.class) {
                if (instance == null) instance = new Singleton3();
            }
        return instance;
    }
}
```
Почему DCL без volatile ломается: `new` — три шага (память, инициализация, присваивание ссылки), JMM может переупорядочить — другой поток увидит ссылку на неинициализированный объект.

<a id="r16-t9"></a>
**9. [Дизайн] Ограничитель частоты на Semaphore.**
```java
class RateLimiter {
    private final Semaphore permits = new Semaphore(0);
    private final ScheduledExecutorService refiller = Executors.newSingleThreadScheduledExecutor();

    RateLimiter(int qps) {
        refiller.scheduleAtFixedRate(() -> {
            permits.drainPermits();        // сброс остатка: bucket не копится бесконечно
            permits.release(qps);          // выдать новую порцию
        }, 0, 1, TimeUnit.SECONDS);
    }
    public boolean allow() { return permits.tryAcquire(); }   // без ожидания: взял — прошёл
    public void shutdown() { refiller.shutdownNow(); }        // обязательно остановить поток-пополнитель!
}
```
Упрощённый token bucket. tryAcquire — неблокирующий отказ; producer'ы токенов нельзя забывать останавливать — утечка потока. Промышленный вариант: Guava RateLimiter, Resilience4j RateLimiter.

<a id="r16-t10"></a>
**10. [Потоки] Как правильно остановить фоновый поток.**
```java
class Worker implements Runnable {
    private volatile boolean running = true;    // volatile — флаг виден из другого потока

    public void stop() { running = false; }

    @Override
    public void run() {
        while (running && !Thread.currentThread().isInterrupted()) {
            try {
                doWork();
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();   // ВОССТАНОВИТЬ флаг — иначе «проглотим» прерывание
                break;
            }
        }
    }
}
```
Thread.stop() — deprecated: снимает мониторы в произвольный момент, объекты остаются в неконсистентном состоянии. Правильно: флаг + interrupt(); interrupt() сбрасывает sleep/join/wait через InterruptedException. Проговорить идиому `interrupt() → catch → restore → break`.

**11. [Потоки] Напечатать числа 1..100 десятью потоками.**
```java
AtomicInteger counter = new AtomicInteger(1);
ExecutorService pool = Executors.newFixedThreadPool(10);
for (int t = 0; t < 10; t++) {
    pool.submit(() -> {
        int v;
        while ((v = counter.getAndIncrement()) <= 100)   // атомарная выдача следующего числа
            System.out.println(Thread.currentThread().getName() + ": " + v);
    });
}
pool.shutdown();
// try { pool.awaitTermination(1, TimeUnit.MINUTES); } catch (InterruptedException e) { ... }
```
Каждое число ровно один раз, порядок недетерминирован. Если требуют строгий порядок — это задача чёт/нечет, обобщённая на 10 потоков (turn 0..9 + условия).

<a id="r16-t12"></a>
**12. [Дизайн] Кэш с ReadWriteLock.**
```java
class SharedCache<K, V> {
    private final Map<K, V> data = new HashMap<>();      // НЕ потокобезопасная — защищаем локами
    private final ReadWriteLock lock = new ReentrantReadWriteLock();

    public V get(K key) {
        lock.readLock().lock();                          // читателей — много одновременно
        try { return data.get(key); }
        finally { lock.readLock().unlock(); }
    }
    public void put(K key, V value) {
        lock.writeLock().lock();                         // писатель — один, читатели ждут
        try { data.put(key, value); }
        finally { lock.writeLock().unlock(); }
    }
}
```
Когда выигрыш: читатели держат лок долго и их много; обновление по промаху — отпустить readLock и перезайти с writeLock (апгрейд лока запрещён — дедлок). Фоллоу-ап: ConcurrentHashMap без лаков.

<a id="r16-t13"></a>
**13. [Потоки] CountDownLatch и CyclicBarrier: скоординировать этапы.**
```java
// CountDownLatch — ОДНОРАЗОВЫЙ: главный ждёт N воркеров
CountDownLatch ready = new CountDownLatch(3);
for (int i = 0; i < 3; i++)
    new Thread(() -> { doWork(); ready.countDown(); }).start();
ready.await();                                  // main продолжит, когда все доложатся
System.out.println("все готовы");

// CyclicBarrier — ПЕРЕИСПОЛЬЗУЕМЫЙ: N потоков встречаются в точке
CyclicBarrier barrier = new CyclicBarrier(3, () -> System.out.println("=== раунд завершён ==="));
for (int i = 0; i < 3; i++)
    new Thread(() -> {
        for (int round = 0; round < 5; round++) {
            doWork();
            try { barrier.await(); }            // ждём остальных — потом новый раунд
            catch (Exception e) { return; }
        }
    }).start();
```
Отличие — любимый вопрос: latch — «ждут все у одной двери, дверь одноразовая»; barrier — «команда бежит этапами, стартует заново». Phaser — если состав участников меняется.

<a id="r16-t14"></a>
**14. [Баг-хантинг] ThreadLocal-контекст: утечка в пуле потоков.**
```java
class RequestContext {
    private static final ThreadLocal<String> USER = new ThreadLocal<>();
    public static void set(String user) { USER.set(user); }
    public static String get()           { return USER.get(); }
    public static void clear()           { USER.remove(); }   // КЛЮЧЕВОЕ
}

// НЕПРАВИЛЬНО: Tomcat/Executors переиспользуют поток между запросами
RequestContext.set("alice");
handleRequest();          // исключение → ThreadLocal остался: следующий запрос увидит «alice»

// ПРАВИЛЬНО:
try {
    RequestContext.set(user);
    handleRequest();
} finally {
    RequestContext.clear();   // очистка обязательна в пулах
}
```
Механика: ThreadLocalMap потока держит ссылку на значение, пока поток жив; в пуле потоков потоки живут вечно → утечка памяти + «чужие» данные. Фоллоу-ап: ThreadLocal со значениями-ClassLoader — классические утечки на перегрузке приложения.

## Раздел 17. CompletableFuture и асинхронность
> Что проверяют: thenApply/thenCompose/thenCombine — какую операцию когда брать, обработку ошибок в цепочке, свой пул под блокирующий IO.

<a id="r17-t1"></a>
**1. [Потоки] Цепочка зависимых вызовов: пользователь → карта → заказ.**
```java
ExecutorService ioPool = Executors.newFixedThreadPool(50);   // свой пул под блокирующие вызовы

CompletableFuture<Order> order = CompletableFuture
    .supplyAsync(() -> api.fetchUser(userId), ioPool)   // User
    .thenApply(User::primaryCard)                       // Card        — синхронное преобразование
    .thenCompose(card -> CompletableFuture.supplyAsync( // Order       — ЗАВИСИМЫЙ асинхронный вызов
        () -> api.fetchOrder(card.orderId()), ioPool));
```
Ключевой вопрос: `thenApply` — преобразование готового значения; `thenCompose` — когда следующий шаг сам асинхронный (аналог flatMap). `thenApply` с CF внутри даст CF<CF<T>>.

<a id="r17-t2"></a>
**2. [Потоки] Два независимых вызова — объединить результат.**
```java
CompletableFuture<Price> price = CompletableFuture.supplyAsync(() -> api.price(id), ioPool);
CompletableFuture<Double> rate  = CompletableFuture.supplyAsync(() -> api.rate(cur), ioPool);

CompletableFuture<Price> adjusted = price.thenCombine(rate, Price::multiply);   // оба готовы — объединяем
```
thenCombine запускает задачи параллельно, не последовательно. Фоллоу-ап: «а если второй нужен и для логики, и для результата» — thenCombine с BiFunction уже это даёт; последовательно — только тогда, когда есть реальная зависимость.

<a id="r17-t3"></a>
**3. [Потоки] Обработка ошибок: exceptionally / handle / whenComplete.**
```java
CompletableFuture<Result> safe = CompletableFuture
    .supplyAsync(() -> risky(), ioPool)
    .handle((res, err) -> {            // вызывается ВСЕГДА; может подменить результат
        if (err != null) {
            log.warn("fallback", err);
            return Result.fallback();
        }
        return res;
    });

// exceptionally — только при ошибке, успех проходит насквозь
// whenComplete — «наблюдатель»: получает (res, err), но НЕ меняет результат (логирование, метрики)
```
Уметь расставить: fallback → exceptionally/handle; сайд-эффект → whenComplete; исключение «внутри» thenApply летит дальше по цепочке до обработчика.

<a id="r17-t4"></a>
**4. [Потоки|hard] Дождаться N параллельных запросов с таймаутом каждого.**
```java
List<CompletableFuture<Stat>> futures = ids.stream()
    .map(id -> fetchStat(id)
        .orTimeout(2, TimeUnit.SECONDS)              // Java 9+: по истечении — TimeoutException
        .exceptionally(e -> Stat.empty()))           // сбой одного не рушит весь список
    .collect(Collectors.toList());

CompletableFuture<List<Stat>> all = CompletableFuture
    .allOf(futures.toArray(CompletableFuture[]::new))   // CompletableFuture<Void> — дождаться всех
    .thenApply(v -> futures.stream()
        .map(CompletableFuture::join)                  // здесь уже всё готово — не бросит
        .collect(Collectors.toList()));
```
Почему join, а не get: checked-исключение не нужно — все ошибки уже обработаны exceptionally. `completeOnTimeout(value, timeout, unit)` — таймаут с дефолтным значением вместо исключения (Java 9+).

<a id="r17-t5"></a>
**5. [Баг-хантинг] supplyAsync с блокирующим IO на общем пуле.**
```java
// ПЛОХО: commonPool рассчитан на CPU-задачи, размер = ядра - 1
CompletableFuture.supplyAsync(() -> httpClient.call(url))    // блокирует воркер общего пула
// 10 таких задач на 8 ядрах → весь параллелизм приложения (и parallelStream!) замерзает:
// ForkJoinPool.commonPool() занят блокирующими вызовами и голодает

// ПРАВИЛЬНО: свой пул под блокирующие вызовы
ExecutorService ioPool = Executors.newFixedThreadPool(50);
CompletableFuture.supplyAsync(() -> httpClient.call(url), ioPool);
```
Правило: CPU-задачи — commonPool (или ForkJoinPool), блокирующий IO — выделенный FixedThreadPool примерно по числу одновременных внешних вызовов. Пул обязан останавливаться при завершении приложения — регистрируем остановку в shutdown-хуке.

<a id="r17-t6"></a>
**6. [Потоки|hard] Ретрай с бэкоффом на CompletableFuture.**
```java
static <T> CompletableFuture<T> retry(int attempts, Supplier<CompletableFuture<T>> op) {
    return op.get().handle((res, err) -> {
        if (err == null) return CompletableFuture.completedFuture(res);
        if (attempts <= 1) return CompletableFuture.<T>failedFuture(err);   // Java 9+
        return retry(attempts - 1, op);                                     // хвостовая композиция
    }).thenCompose(cf -> cf);   // разворачиваем CF<CF<T>> в CF<T>
}
```
handle возвращает CF<CF<T>>, поэтому thenCompose flattens. Фоллоу-апы: пауза между попытками — `CompletableFuture.delayedExecutor(delay, unit)` (Java 9+); ретраить только retryable-ошибки; максимальная глубина. Библиотеки: resilience4j-retry.

## Раздел 18. Stream API и функциональный стиль
> Что проверяют: коллекционеры (groupingBy семейство), flatMap, отсутствие состояния в лямбдах, когда parallel вредит.

Для задач раздела:
```java
record Employee(String name, String dept, String city, int salary) { }
record Order(String customer, int amount) { }
```

<a id="r18-t1"></a>
**1. [Стримы] Сгруппировать сотрудников по отделам.**
```java
Map<String, List<Employee>> byDept = employees.stream()
    .collect(Collectors.groupingBy(Employee::dept));
```
База. Фоллоу-ап: внизу Map с предсказуемым порядком — `groupingBy(classifier, LinkedHashMap::new, toList())`.

<a id="r18-t2"></a>
**2. [Стримы] Средняя зарплата по отделу и двухуровневая группировка.**
```java
Map<String, Double> avgByDept = employees.stream()
    .collect(Collectors.groupingBy(Employee::dept, Collectors.averagingInt(Employee::salary)));

Map<String, Map<String, List<Employee>>> byCityThenDept = employees.stream()

```
Вложенные коллекторы читаются «изнутри наружу». Уметь объяснить разницу downstream-коллектора и внешнего.

<a id="r18-t3"></a>
**3. [Стримы] Топ-3 по зарплате; минимум в каждом отделе.**
```java
List<Employee> top3 = employees.stream()
    .sorted(Comparator.comparingInt(Employee::salary).reversed())
    .limit(3)
    .collect(Collectors.toList());

Employee best = employees.stream()
    .max(Comparator.comparingInt(Employee::salary))
    .orElseThrow(() -> new NoSuchElementException("пустой список"));

Map<String, Optional<Employee>> minPerDept = employees.stream()
    .collect(Collectors.groupingBy(Employee::dept,
        Collectors.minBy(Comparator.comparingInt(Employee::salary))));
```
`Optional` в значении — цена группировки (отдел может быть без... нет, в groupingBy отдел существует только если есть элементы — Optional никогда не пуст; упомянуть `Collectors.collectingAndThen` чтобы избавиться от Optional).

**10. [Баг-хантинг] Parallel stream: три способа выстрелить в ногу.**

## Раздел 19. ООП: значимые классы и мини-системы
> Что проверяют: иммутабельность, equals/hashCode, BigDecimal для денег, инкапсуляцию состояния, выбор между классом/record/enum.

<a id="r19-t1"></a>
**1. [Дизайн] Класс Money.**
```java
enum Currency { USD, EUR, RUB }

final class Money implements Comparable<Money> {
    private final BigDecimal amount;      // деньги — НИКОГДА double (0.1 + 0.2 != 0.3)
    private final Currency currency;

    Money(BigDecimal amount, Currency currency) {
        this.amount = amount.setScale(2, RoundingMode.HALF_EVEN);   // банковское округление до копеек
        this.currency = currency;
    }
    static Money of(String s, Currency c) { return new Money(new BigDecimal(s), c); }

    Money add(Money other)      { requireSameCurrency(other); return new Money(amount.add(other.amount), currency); }
    Money multiply(int times)   { return new Money(amount.multiply(BigDecimal.valueOf(times)), currency); }

    private void requireSameCurrency(Money other) {
        if (currency != other.currency)
            throw new IllegalArgumentException("валюты не совпадают: " + currency + " vs " + other.currency);
    }

    @Override public int compareTo(Money o) { requireSameCurrency(o); return amount.compareTo(o.amount); }
    @Override public boolean equals(Object o) {
        return o instanceof Money m && currency == m.currency && amount.compareTo(m.amount) == 0;
    }
    @Override public int hashCode() { return Objects.hash(currency, amount.stripTrailingZeros()); }
    @Override public String toString() { return currency + " " + amount; }
}
```
Три столпа ответа: 1) BigDecimal (и конструктор из String, не из double); 2) equals через compareTo — BigDecimal.equals учитывает scale: `2.0` не равно `2.00`; 3) проверка валюты в операциях, иммутабельность каждой операции.

<a id="r19-t2"></a>
**2. [Дизайн] Диапазон значений на дженериках.**
```java
record Range<T extends Comparable<T>>(T from, T to) {
    public Range {                                        // компактный конструктор с валидацией
        if (from.compareTo(to) > 0) throw new IllegalArgumentException("from > to");
    }
    boolean contains(T v)        { return from.compareTo(v) <= 0 && v.compareTo(to) <= 0; }
    boolean overlaps(Range<T> o) { return from.compareTo(o.to) <= 0 && o.from.compareTo(to) <= 0; }

    Optional<Range<T>> merge(Range<T> o) {                // объединение пересекающихся
        if (!overlaps(o)) return Optional.empty();
        return Optional.of(new Range<>(min(from, o.from), max(to, o.to)));
    }
    private T min(T a, T b) { return a.compareTo(b) <= 0 ? a : b; }
    private T max(T a, T b) { return a.compareTo(b) >= 0 ? a : b; }
}
```
Bounded type parameter + record с валидацией. Спросят: почему `extends Comparable` в типе (нужен compareTo); что вернёт merge для касающихся диапазонов (пересеклись — сольются).

<a id="r19-t3"></a>
**3. [Дизайн] Потокобезопасный банковский счёт и перевод.**
```java
class Account {
    private final long id;
    private long balance;                      // в копейках: long, а не double

    Account(long id, long balance) { this.id = id; this.balance = balance; }

    synchronized void deposit(long amount) {
        requirePositive(amount);
        balance += amount;
    }
    synchronized void withdraw(long amount) {
        requirePositive(amount);
        if (balance < amount) throw new IllegalStateException("недостаточно средств: " + balance);
        balance -= amount;
    }
    synchronized long balance() { return balance; }

    // ДЕДЛОК-ОПАСНО: transfer(a, b) и transfer(b, a) одновременно захватят локи в разном порядке
    static void transfer(Account from, Account to, long amount) {
        Account first  = from.id < to.id ? from : to;   // ЕДИНЫЙ порядок захвата по id
        Account second = from.id < to.id ? to : from;
        synchronized (first) {
            synchronized (second) {
                from.withdraw(amount);
                to.deposit(amount);
            }
        }
    }
    private static void requirePositive(long amount) {
        if (amount <= 0) throw new IllegalArgumentException("сумма должна быть положительной");
    }
}
```
Разворот задачи на дедлок (см. раздел 16): без упорядочения — классический взаимный блок. Фоллоу-ап: tryLock с откатом; атомарность перевода при отсутствии денег (откат не нужен — withdraw кинет до deposit).

<a id="r19-t4"></a>
**4. [Дизайн] Конечный автомат заказа.**
```java
enum OrderStatus {
    NEW, PAID, SHIPPED, DELIVERED, CANCELLED;

    public Set<OrderStatus> next() {
        return switch (this) {
            case NEW      -> Set.of(PAID, CANCELLED);
            case PAID     -> Set.of(SHIPPED, CANCELLED);
            case SHIPPED  -> Set.of(DELIVERED);
            case DELIVERED, CANCELLED -> Set.of();       // терминальные
        };
    }
    public boolean canMoveTo(OrderStatus target) { return next().contains(target); }
}

class Order {
    private OrderStatus status = OrderStatus.NEW;
    public synchronized void moveTo(OrderStatus target) {
        if (!status.canMoveTo(target))
            throw new IllegalStateException("недопустимый переход " + status + " -> " + target);
        status = target;
    }
    public OrderStatus status() { return status; }
}
```
Переходы локализованы в enum — новая логика не меняет старые состояния. Сравнить с switch-по-месту (правки размазаны) — аргумент за enum-метод.

<a id="r19-t5"></a>
**5. [Дизайн] Иерархия фигур на sealed + record.**
```java
sealed interface Shape permits Circle, Square, Rect { }
record Circle(double r) implements Shape { }
record Square(double a) implements Shape { }
record Rect(double w, double h) implements Shape { }

static double area(Shape s) {
    return switch (s) {                       // exhaustive: default НЕ нужен — sealed закрыл множество
        case Circle c -> Math.PI * c.r() * c.r();
        case Square q -> q.a() * q.a();
        case Rect   r -> r.w() * r.h();
    };
}

List<Shape> byArea = shapes.stream()
    .sorted(Comparator.comparingDouble(s -> area((Shape) s)))
    .collect(Collectors.toList());
```
Sealed (Java 17): «алгебраическая» сумма типов; компилятор проверит полноту switch; добавление новой фигуры = ошибка компиляции во всех старых switch — сразу видно, где дописать. Отличный повод поговорить про иммутабельность record и ограничения sealed.

<a id="r19-t6"></a>
**6. [Дизайн] Пара значений и потокобезопасный кэш-загрузчик.**
```java
record Pair<A, B>(A first, B second) { }

class Cache<K, V> {
    private final Map<K, V> store = new ConcurrentHashMap<>();

    public V getOrCompute(K key, Function<K, V> loader) {
        return store.computeIfAbsent(key, loader);   // атомарно для ключа: лоадер не вызовется дважды
    }
    public int size() { return store.size(); }
}
```
computeIfAbsent в ConcurrentHashMap выполняет loader под локом бакета: параллельные запросы одного ключа получат один вызов loader. Фоллоу-ап: долгий loader блокирует бакет (а в старых версиях — весь map) → считать в будущем значении: `Map<K, CompletableFuture<V>>`.

**7. [С_нуля] Итератор по матрице.**
```java
class Matrix implements Iterable<Integer> {
    private final int[][] data;
    Matrix(int[][] data) { this.data = data; }

    @Override
    public Iterator<Integer> iterator() {
        return new Iterator<>() {
            int row, col;
            @Override public boolean hasNext() {           // пропускаем исчерпанные/пустые строки
                while (row < data.length && col == data[row].length) { row++; col = 0; }
                return row < data.length;
            }
            @Override public Integer next() {
                if (!hasNext()) throw new NoSuchElementException();
                return data[row][col++];
            }
        };
    }
}
// for (int v : matrix) — работает благодаря Iterable
```
Тонкое место: `col == data[row].length` корректно и для пустых строк (длина 0). Вопрос на понимание контракта итератора (next без hasNext → исключение).

## Раздел 20. Паттерны проектирования за 15 минут
> Что проверяют: не «расскажи про паттерн», а «примени здесь». Решения на современных средствах Java (enum, record, лямбды) ценятся выше громоздких GoF-классов.

<a id="r20-t1"></a>
**1. [Дизайн] Strategy: способы оплаты.**
```java
enum PaymentType { CARD, CASH, CRYPTO }

// классика через интерфейс:
interface PaymentStrategy { Receipt pay(Order o); }
class CardPayment implements PaymentStrategy { /* ... */ }

// современно — Map стратегий (ламбды/ссылки на методы):
Map<PaymentType, Function<Order, Receipt>> strategies = Map.of(
```

**2. [Дизайн] Observer: шина событий.**

**3. [Дизайн] Decorator: кофе с добавками.**

**4. [Дизайн] Фабрика уведомлений.**

<a id="r20-t5"></a>
**5. [Дизайн] Proxy: кэширующая обёртка.**
```java
interface UserService { User load(long id); }

class CachingUserService implements UserService {
    private final UserService delegate;
    private final Map<Long, Optional<User>> cache = new ConcurrentHashMap<>(); // кэшируем и «нет такого»

    CachingUserService(UserService delegate) { this.delegate = delegate; }

    @Override
    public User load(long id) {
        return cache.computeIfAbsent(id, k -> Optional.ofNullable(delegate.load(k)))
                    .orElseThrow(() -> new NoSuchElementException("user " + id));
    }
}
```
Кэширование Optional.empty — «негативный кэш»: повторные запросы несуществующих id не бьют в БД. Фоллоу-ап: TTL и вытеснение — поверх Caffeine, а не руками.

<a id="r20-t6"></a>
**6. [Дизайн|hard] Chain of Responsibility: пайплайн middleware.**
```java
record Request(String token, String path) { }
record Response(int code, String body) { }
@FunctionalInterface
interface Handler { Response handle(Request r); }

class Middleware {
    private final List<Function<Handler, Handler>> layers = new ArrayList<>();

    public Middleware use(Function<Handler, Handler> layer) {   // слой = обёртка над следующим
        layers.add(layer);
        return this;
    }
    public Response run(Request req) {
        Handler pipeline = r -> new Response(200, "ok");        // финальный обработчик
        for (int i = layers.size() - 1; i >= 0; i--)            // собираем «матрёшку» изнутри
            pipeline = layers.get(i).apply(pipeline);
        return pipeline.handle(req);
    }
}
// использование:
Middleware mw = new Middleware();
mw.use(next -> r -> r.token() == null
    ? new Response(401, "unauthorized")
    : next.handle(r));
mw.use(next -> r -> {
    log.info(r.path());
    return next.handle(r);
});
Response resp = mw.run(new Request("jwt...", "/api/orders"));
```
Каждый слой решает: обработать самому или передать дальше. Сборка с хвоста — чтобы первый `use` оказался внешним. Прямая отсылка к фильтрам Servlet/Spring — проговорить.

## Раздел 21. Баг-хантинг
> Формат «найди баг» встречается на middle всё чаще: смотрят на читку чужого кода и знание JMM/контрактов. Во всех задачах: сначала назвать баг вслух, потом — минимальный фикс.

<a id="r21-t1"></a>
**1. [Баг-хантинг] ConcurrentModificationException.**
```java
List<String> names = new ArrayList<>(List.of("ann", "bob", "cyd"));
for (String n : names)
    if (n.equals("bob")) names.remove(n);        // ConcurrentModificationException

// фиксы:
for (Iterator<String> it = names.iterator(); it.hasNext(); )   // 1) итератор с remove
    if (it.next().equals("bob")) it.remove();
names.removeIf("bob"::equals);                                  // 2) идеоматично (внутри — тот же итератор)
List<String> copy = List.copyOf(names);                          // 3) итерация по копии, удаление из оригинала
```
Механика: modCount проверяется на каждом next(); remove через коллекцию его увеличивает мимо итератора. removeIf — единственный корректный «одной строкой».

<a id="r21-t2"></a>
**2. [Баг-хантинг] Сравнение Integer через ==.**
```java
Integer a = 127, b = 127;
System.out.println(a == b);     // true  — Integer.valueOf кэширует значения [-128, 127]
Integer c = 128, d = 128;
System.out.println(c == d);     // false — разные объекты вне кэша
Integer e = new Integer(127);   // deprecated, но живёт в старом коде
System.out.println(e == a);     // false — new всегда новый объект
```
Правило: ссылочные типы — только equals(). Гадость бага в том, что «работает» на малых числах и в тестах, а падает в проде 29-го числа месяца (id пересёк 127).

<a id="r21-t3"></a>
**3. [Баг-хантинг] equals без hashCode.**
```java
class Point {
    final int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }
    @Override public boolean equals(Object o) {
        return o instanceof Point p && p.x == x && p.y == y;
    }
    // hashCode НЕ переопределён
}
Set<Point> points = new HashSet<>();
points.add(new Point(1, 2));
System.out.println(points.contains(new Point(1, 2)));   // false: другой hashCode → ищем не в том бакете
map.put(new Point(1, 2), "a");
System.out.println(map.get(new Point(1, 2)));           // null — «потеряли» значение
```
Контракт: равные объекты обязаны иметь равный hashCode; иначе хеш-структуры ведут себя как описано. Фикс: `Objects.hash(x, y)`.

<a id="r21-t4"></a>
**4. [Баг-хантинг] SimpleDateFormat как статическое поле.**
```java
class DateFormatter {
    private static final SimpleDateFormat FMT = new SimpleDateFormat("yyyy-MM-dd");
    static String format(Date d) { return FMT.format(d); }   // гонка: SimpleDateFormat НЕ потокобезопасен
}
// симптомы: то правильная дата, то «прыжки» года на 1970/3900, NumberFormatException
// фикс (Java 8+): DateTimeFormatter — immutable и потокобезопасен
private static final DateTimeFormatter FMT = DateTimeFormatter.ofPattern("yyyy-MM-dd");
static String format(LocalDate d) { return d.format(FMT); }
```
Баг коварен малой воспроизводимостью: проявляется под нагрузкой. Альтернативный фикс — ThreadLocal<SimpleDateFormat>, но новый API лучше.

<a id="r21-t5"></a>
**5. [Баг-хантинг] Double-checked locking без volatile.**
```java
class Lazy {
    private static Lazy instance;                    // нет volatile!
    public static Lazy instance() {
        if (instance == null)
            synchronized (Lazy.class) {
                if (instance == null) instance = new Lazy();
            }
        return instance;                             // другой поток видит НЕДОСТРОЕННЫЙ объект
    }
}
```
`new` — выделение памяти + инициализация полей + запись ссылки; переупорядочение шагов допустимо. Фикс: `volatile` (happens-before на запись/чтение) или holder-идиома. Показать связку с задачей про синглтоны в разделе 16.

<a id="r21-t6"></a>
**6. [Баг-хантинг] wait() вне synchronized.**
```java
Object monitor = new Object();
synchronized (monitor) { /* подготовка */ }
monitor.wait();        // IllegalMonitorStateException: ждём без захваченного монитора

// правильная форма:
synchronized (monitor) {
    while (!ready)     // и только while — если пробуждение ложное
        monitor.wait();
}
```
wait снимает лок и усыпляет; вызов без лока — исключение (JLS требует владение монитором). Тот же сюжет у notify/notifyAll.

<a id="r21-t7"></a>
**7. [Баг-хантинг] return в finally.**
```java
static int f() {
    try { return 1; }
    finally { return 2; }        // вернёт 2: finally выполняется ПОСЛЕ вычисления return, но ДО возврата
}
static int g() {
    int x = 1;
    try { return x; }
    finally { x = 99; }          // вернёт 1: значение уже скопировано в возвращаемый слот
}
```
finally с return/throw глотает и результат try, и его исключение. Правило: finally — только очистка (close, unlock-семантика), никаких управляемых возвратов.

<a id="r21-t8"></a>
**8. [Баг-хантинг] Утёкшая инкапсуляция.**
```java
class Team {
    private final List<String> members = new ArrayList<>(List.of("ann", "bob"));
    public List<String> getMembers() { return members; }   // наружу ушла живая ссылка
}
team.getMembers().add("mallory");       // «неизменяемый» Team мутировал извне

// фикс:
public List<String> getMembers() { return List.copyOf(members); }        // копия (Java 10+)
public List<String> getMembers() { return Collections.unmodifiableList(members); } // представление: само меняться будет под ним
```
Разницу List.copyOf (снимок) и unmodifiableList (view поверх оригинала) спросят обязательно. То же для массивов: геттер массива — всегда clone().

<a id="r21-t9"></a>
**9. [Баг-хантинг] Check-then-act на HashMap.**
```java
Map<Long, Cart> carts = new HashMap<>();          // общий на все запросы
Cart c = carts.get(userId);
if (c == null)
    carts.put(userId, new Cart());                // гонка: два потока увидели null, две корзины
// а при конкурентном resize HashMap может построить цикл в бакетах — get() повиснет НАВСЕГДА

// фикс:
Map<Long, Cart> carts = new ConcurrentHashMap<>();
Cart c = carts.computeIfAbsent(userId, Cart::new); // атомарно
```
HashMap под конкурентной записью — UB на уровне JDK: потерянные записи, бесконечный цикл (до Java 8 «зацикливание» — известная история prod-инцидентов). Единственный фикс — concurrent-структура.

<a id="r21-t10"></a>
**10. [Баг-хантинг] Мутабельный ключ в HashSet.**
```java
List<Integer> key = new ArrayList<>(List.of(1));
Map<List<Integer>, String> map = new HashMap<>();
map.put(key, "первый");
key.add(2);                                       // hashCode ключа ИЗМЕНИЛСЯ
System.out.println(map.get(key));                 // null — запись «в другом бакете»
System.out.println(map.containsKey(List.of(1)));  // false — и по старому значению тоже не найти: ключ-то теперь [1, 2]
```
Ключи хеш-структур обязаны быть неизменяемыми (или хотя бы не мутировать hash-значимые поля). Фикс: `List.of(...)` / record / String в качестве ключа.

<a id="r21-t11"></a>
**11. [Баг-хантинг] Проглоченное исключение.**
```java
try {
    save(order);
} catch (Exception e) {
    log.error("не сохранилось", e);     // залогировали — и молча продолжили «успешный» сценарий
}
chargeCustomer(order);                  // клиент платит за несуществующий заказ

// фикс: наверх с сохранением причины
catch (Exception e) {
    throw new OrderPersistenceException("order " + order.id(), e);   // e — причина, стектрейс цел
}
```
Два поучения: (1) лог ≠ обработка — если метод не может честно продолжить, исключение летит выше; (2) оборачивание без передачи причины (`new X(e.getMessage())`) выбрасывает стектрейс — всегда передавать `e` последним аргументом.

<a id="razdel-22"></a>
## Раздел 22. Рефакторинг
> Формат «улучши код, сохранив поведение»: оценивается способность видеть запахи кода и малыми шагами улучшать. Проговаривай каждый шаг — интервьюер оценивает ход мысли.

<a id="r22-t1"></a>
**1. [Рефакторинг] Пирамида вложенных if → guard clauses.**
```java
// ДО
double orderTotal(Order o) {
    if (o != null) {
        if (o.items() != null) {
            if (!o.items().isEmpty()) {
                double sum = 0;
                for (Item i : o.items()) sum += i.price() * i.qty();
                return sum;
            } else return 0;
        } else return 0;
    } else throw new IllegalArgumentException();
}
// ПОСЛЕ
double orderTotal(Order o) {
    if (o == null) throw new IllegalArgumentException("order");
    List<Item> items = o.items() == null ? List.of() : o.items();
    return items.stream().mapToDouble(i -> i.price() * i.qty()).sum();
}
```
Принцип: «возвращайся как можно раньше». Основной сценарий остаётся на нулевом уровне вложенности.

<a id="r22-t2"></a>
**2. [Рефакторинг] Цепочка null-проверок → Optional.**
```java
// ДО
String city = null;
if (user != null) {
    Address addr = user.getAddress();
    if (addr != null) city = addr.getCity();
}

// ПОСЛЕ
Optional<String> city = Optional.ofNullable(user)
    .map(User::getAddress)
    .map(Address::getCity);
String resolved = city.orElse("не указан");
```
Сразу оговорить (спрашивают!): Optional — тип возврата, а не тип поля/параметра; `orElseGet` против eager `orElse`; не `Optional.get()` без проверки.

<a id="r22-t3"></a>
**3. [Рефакторинг] Императивный цикл → конвейер стрима.**
```java
// ДО
List<String> names = new ArrayList<>();
for (Employee e : employees)
    if (e.salary() > 100_000 && e.dept().equals("IT"))
        names.add(e.name().toUpperCase());

// ПОСЛЕ
List<String> names = employees.stream()
    .filter(e -> e.dept().equals("IT"))
    .filter(e -> e.salary() > 100_000)
    .map(e -> e.name().toUpperCase())
    .collect(Collectors.toList());
```
Шаги рефакторинга называть вслух: фильтры вперёд (меньше работы дальше), map в конце. Сказать, когда цикл лучше: побочные эффекты, break по сложному условию, изменение нескольких коллекций.

<a id="r22-t4"></a>
**4. [Рефакторинг] switch по коду типа → полиморфизм.**
```java
// ДО: тип в поле, поведение размазано по switch
double area(ShapeData s) {
    return switch (s.type()) {
        case CIRCLE -> Math.PI * s.r() * s.r();
        case RECT   -> s.w() * s.h();
        default -> throw new IllegalStateException();
    };
}
// и ещё switch в toString(), в validate(), в export()...

// ПОСЛЕ: поведение живёт рядом с данными
sealed interface Shape permits Circle, Rect { double area(); }
record Circle(double r) implements Shape { public double area() { return Math.PI * r * r; } }
record Rect(double w, double h) implements Shape { public double area() { return w * h; } }
```
Признак к рефакторингу: switch по одному и тому же полю в нескольких местах. Новая фигура = новый класс, нулевые правки существующих.

<a id="r22-t5"></a>
**5. [Рефакторинг] Магические строки → enum.**
```java
// ДО: опечатка = тихий баг, автодополнение не поможет
if (user.getRole().equals("ADIN")) return false;
// ...и так в 20 местах

// ПОСЛЕ
enum Role { ADMIN, USER, SUPPORT }
if (user.role() != Role.ADMIN) return false;
```
Область значений фиксируется компилятором; enum умеет методы и поля (права доступа). String остаётся только на границах (DTO/БД) + маппинг в enum раз в одном месте.

<a id="r22-t6"></a>
**6. [Рефакторинг] Телескопический конструктор → объект-параметр.**
```java
// ДО
createOrder(userId, sku, qty, currency, gift, promo, note, urgent);   // 8 параметров, 4 перегрузки

// ПОСЛЕ
record OrderRequest(String userId, String sku, int qty, Currency currency,
                    boolean gift, Optional<String> promo) {
    public OrderRequest {                                  // валидация в одном месте
        if (qty < 1) throw new IllegalArgumentException("qty");
    }
}
void createOrder(OrderRequest req) { /* ... */ }
```
Record-параметр: иммутабелен, самодокументируем, расширяется без ломки сигнатур. Для дефолтов и пошаговой сборки — билдер (см. раздел 19).

<a id="r22-t7"></a>
**7. [Рефакторинг] Три почти одинаковых цикла → дженерик-метод.**
```java
// ДО: groupEmployeesByDept(), groupOrdersByCustomer(), groupUsersByCity() — копипаст

// ПОСЛЕ
static <T, K> Map<K, List<T>> groupBy(Collection<T> items, Function<T, K> key) {
    Map<K, List<T>> res = new HashMap<>();
    for (T item : items)
        res.computeIfAbsent(key.apply(item), k -> new ArrayList<>()).add(item);
    return res;
}
Map<String, List<Employee>> byDept = groupBy(employees, Employee::dept);
Map<String, List<Order>> byCustomer = groupBy(orders, Order::customer);
```
Функция-ключ — единственная точка различия. Проверить: поведение сохранено, дженерик не «переусложнён» (одна ответственность).

<a id="r22-t8"></a>
**8. [Рефакторинг] Разбор god-метода (ход рассуждений).**
Дан метод `processRequest(...)` на 300 строк: валидация, авторизация, тарификация, запись в БД, уведомления, логи — всё в одном.
Шаги, которые ожидают услышать:
1. Выделить «абзацы» по пустым строкам/комментариям — кандидаты в Extract Method.
2. Именовать каждый по глаголу бизнес-действия: `validate`, `authorize`, `charge`, `persist`, `notify`.
3. Ввести объект-контекст (record `RequestContext`), чтобы не таскать 10 параметров.
4. Побочные эффекты (логи, метрики) — декораторами/перехватчиками, а не внутрь логики.
5. Разные уровни абстракции не смешивать: метод либо оркестрирует, либо делает работу.
6. После каждого шага — тесты зелёные (малые безопасные шажки, не «перепишем всё»).
```java
Response processRequest(Request r) {
    RequestContext ctx = validate(r);          // бросает IllegalArgumentException
    authorize(ctx);
    charge(ctx);
    Order saved = persist(ctx);
    notify(saved);
    return Response.ok(saved.id());
}
```

<a id="razdel-23"></a>
## Раздел 23. Паззлы «что выведет»
> Формат — «прочитай код вслух и предскажи вывод». Главное не угадать, а объяснить правило, по которому JVM себя ведёт.

<a id="r23-t1"></a>
**1. [Вывод] Кэш Integer.**
```java
Integer a = 127, b = 127;
System.out.println(a == b);   // true
Integer c = 128, d = 128;
System.out.println(c == d);   // false
System.out.println(c.equals(d));   // true
```
Объяснение: автобоксинг вызывает `Integer.valueOf`, который кэширует значения от −128 до 127 (`IntegerCache`); вне диапазона создаются разные объекты, и `==` для ссылок сравнивает адреса. Обобщение: `==` для примитивов — значение, для ссылок — тождество; упакованные типы всегда через equals.

<a id="r23-t2"></a>
**2. [Вывод] Пул строк и конкатенация.**
```java
String a = "hello";
String b = "hello";
String c = new String("hello");
String d = "hel" + "lo";                // склеится компилятором
String e = "hel" + new String("lo");    // вычислится в рантайме

System.out.println(a == b);              // true  — один объект в пуле литералов
System.out.println(a == c);              // false — new всегда новый объект
System.out.println(a == d);              // true  — константное сворачивание: литералы склеены на компиляции
System.out.println(a == e);              // false — в рантайме StringBuilder, объект мимо пула
System.out.println(a == e.intern());     // true  — intern вернёт объект из пула
System.out.println(a.equals(c));         // true  — содержимое одинаково
```
Ключевые правила: литералы интернируются; конкатенация двух констант сворачивается компилятором; конкатенация с runtime-значением — нет.

<a id="r23-t3"></a>
**3. [Вывод] finally и возврат значения.**
```java
static int demo1() {
    try { return 1; }
    finally { System.out.println("finally"); }   // напечатается ДО возврата
}
static int demo2() {
    try { return 1; }
    finally { return 2; }                          // вернёт 2 — затирает результат try
}
static int demo3() {
    int x = 1;
    try { return x; }
    finally { x = 99; }                            // вернёт 1 — значение уже скопировано
}
```
Порядок JVM: вычислить return-выражение → выполнить finally → вернуть. Изменение локальной переменной в finally уже не влияет на скопированный результат, а return/throw в finally — влияют (и это антипаттерн).

<a id="r23-t4"></a>
**4. [Вывод] Порядок инициализации класса и объекта.**
```java
class Parent {
    static { System.out.println("1. static Parent"); }
    { System.out.println("3. init Parent"); }
    Parent() { System.out.println("4. ctor Parent"); }
}
class Child extends Parent {
    static { System.out.println("2. static Child"); }
    { System.out.println("5. init Child"); }
    Child() { System.out.println("6. ctor Child"); }
}
new Child();
// вывод:
// 1. static Parent
// 2. static Child        (статика — один раз, при первой загрузке класса, родитель раньше)
// 3. init Parent         (далее — на каждый new: блоки инициализации ПОСЛЕ super(), ПЕРЕД телом конструктора)
// 4. ctor Parent
// 5. init Child
// 6. ctor Child
```
Порядок запоминать как: статика (родитель → потомок, единожды) → для каждого объекта: super() → init-блоки своего уровня → конструктор.

<a id="r23-t5"></a>
**5. [Вывод] Unboxing в условии тернарника.**
```java
Boolean flag = null;
System.out.println(flag ? "да" : "нет");    // NullPointerException!

Integer boxed = null;
int ok   = (boxed != null) ? boxed : 0;     // ОК: guard-проверка защищает
int boom = true ? boxed : 0;                // NPE: тип выражения int — boxed распаковывается
```
Условие `Boolean` неявно распаковывается в boolean: null → NPE. Во второй паре: приоритет разрешения перегрузок делает `Integer?int` выражением типа int, и выбранная null-ветка распаковывается. Объяснять через «тернарник с смешанными Integer/int распаковывает обе ветки при определении типа».

<a id="r23-t6"></a>
**6. [Вывод] Инкремент и выбор перегрузки.**
```java
int i = 0;
i = i++;
System.out.println(i);        // 0: постфикс вернул СТАРОЕ значение, инкремент — во временную переменную

static void f(int x)      { System.out.println("int"); }
static void f(Integer x)  { System.out.println("Integer"); }
static void f(int... x)   { System.out.println("varargs"); }

f(5);                       // int      — точное совпадение
f((short) 5);               // int      — расширение short→int ближе, чем боксинг
f(Integer.valueOf(5));      // Integer  — точное совпадение по ссылке
f(new int[]{5});            // varargs  — только он и подходит
// приоритет: точное совпадение > расширение примитива > боксинг > varargs
```
`i = i++` — вычислить i (0) → увеличить i (1) → присвоить сохранённое 0. Финал: i == 0. Приоритет фаз разрешения перегрузок — редкий, но «элитный» вопрос на middle.

<a id="razdel-24"></a>
## Раздел 24. Тестирование
> Проверяют: структуру теста (given/when/then), охват краёв, параметризацию, поведение моков (а не «какую кнопку нажать в Mockito»).

<a id="r24-t1"></a>
**1. [Тесты] Юнит-тесты для FizzBuzz-подобной функции.**
Требование: `fb(n)`: кратно 3 → "Fizz", кратно 5 → "Buzz", 15 → "FizzBuzz", иначе число; n < 1 → IllegalArgumentException.
```java
@Test
void fizzBuzzCoversAllBranches() {
    assertAll(
        () -> assertEquals("1", fb(1)),
        () -> assertEquals("2", fb(2)),
        () -> assertEquals("Fizz", fb(3)),
        () -> assertEquals("Buzz", fb(5)),
        () -> assertEquals("FizzBuzz", fb(15)),
        () -> assertEquals("FizzBuzz", fb(30)),
        () -> assertEquals("7", fb(7)),
        () -> assertThrows(IllegalArgumentException.class, () -> fb(0)),
        () -> assertThrows(IllegalArgumentException.class, () -> fb(-15))
    );
}
```
Проговорить структуру: каждая ветка кода покрыта + обе границы ошибки. Отдельный happy-path и отдельный edge-case — тоже нормальная альтернатива вместо assertAll.

<a id="r24-t2"></a>
**2. [Тесты] Параметризованные тесты.**
```java
@ParameterizedTest
@ValueSource(ints = {3, 6, 9, 99})
void fizz(int n) { assertEquals("Fizz", fb(n)); }

@ParameterizedTest(name = "{0} -> {1}")
@CsvSource({ "1, 1", "3, Fizz", "5, Buzz", "15, FizzBuzz" })
void table(int input, String expected) { assertEquals(expected, fb(input)); }
```
CsvSource-таблица = table-driven подход: один прогон на строку, имя теста подставляет параметры — падение сразу показывает ввод. Упомянуть `@MethodSource` для сложных объектов.

<a id="r24-t3"></a>
**3. [Тесты] Проверка исключений.**
```java
@Test
void withdrawMoreThanBalanceThrows() {
    Account acc = new Account(100);
    InsufficientFundsException e = assertThrows(InsufficientFundsException.class,
        () -> acc.withdraw(500));
    assertEquals(100, e.available());     // assertThrows ВОЗВРАЩАЕТ исключение — проверяем детали
    assertEquals(500, e.requested());
}

@Test
void balanceUnchangedAfterFailedWithdraw() {
    Account acc = new Account(100);
    assertThrows(InsufficientFundsException.class, () -> acc.withdraw(500));
    assertEquals(100, acc.balance());     // инвариант состояния после ошибки
}
```
Уровни проверки: тип исключения → сообщение/поля → состояние системы после сбоя (часто забывают).

<a id="r24-t4"></a>
**4. [Тесты] Мок зависимости и верификация взаимодействий.**
```java
@Test
void secondLoadHitsCacheNotRepo() {
    UserRepo repo = mock(UserRepo.class);                       // Mockito
    when(repo.findById(42L)).thenReturn(Optional.of(new User(42L, "ann")));
    UserService service = new UserService(repo);

    service.load(42L);
    service.load(42L);

    verify(repo, times(1)).findById(42L);      // в БД сходили ровно один раз
    // ненужные взаимодействия тоже проверяем:
    verifyNoMoreInteractions(repo);
}
```
Проговорить границы моков: мокаем только владение-границей (репозиторий, шлюз), НЕ мокаем value-объекты и утилиты; состояние сервиса проверяем на реальном объекте. `verify` — про взаимодействие, `assertEquals` — про результат: тест должен проверять хоть что-то без verify.

## Раздел 25. Date/Time API и файловый ввод-вывод
> Что проверяют: java.time вместо Date/Calendar, Period против Duration, try-with-resources, потоковую обработку файлов.

<a id="r25-t1"></a>
**1. [Классика] Возраст в полных годах.**
```java
static int age(LocalDate birth, LocalDate today) {
    return Period.between(birth, today).getYears();
}
// нюанс 29 февраля: Period.between корректно вернёт год и в невисокосном году (28.02+1 день = 01.03)
```
Фоллоу-ап: «сколько дней до следующего дня рождения» — `ChronoUnit.DAYS.between(today, nextBirthday)`; почему НЕ `(today.toEpochDay() - birth.toEpochDay()) / 365` (високосные).

<a id="r25-t2"></a>
**2. [Классика] Прибавить N рабочих дней.**
```java
static LocalDate plusBusinessDays(LocalDate date, int days) {
    LocalDate res = date;
    int added = 0;
    while (added < days) {
        res = res.plusDays(1);
        DayOfWeek dow = res.getDayOfWeek();
        if (dow != DayOfWeek.SATURDAY && dow != DayOfWeek.SUNDAY) added++;
    }
    return res;
}
```
Ограничение озвучить: праздники не учтены — нужен календарь праздников (список дат или ProductionCalendar-зависимость). Period — календарные единицы, Duration — точные секунды: это различие спрашивают почти всегда.

<a id="r25-t3"></a>
**3. [Классика] Частота слов в файле.**
```java
try (Stream<String> lines = Files.lines(Path.of("book.txt"))) {   // Stream нужно ЗАКРЫВАТЬ — дескриптор файла!
    Map<String, Long> freq = lines
        .flatMap(l -> Arrays.stream(l.split("\\W+")))
        .filter(w -> !w.isEmpty())
        .collect(Collectors.groupingBy(String::toLowerCase, Collectors.counting()));
    System.out.println(freq.getOrDefault("the", 0L));
}
```
Три обязательных пункта: try-with-resources над stream от Files (иначе утечка дескриптора), Files.lines — лениво и не грузит файл в память, большие файлы — ок; кодировка: `Files.lines(path, StandardCharsets.UTF_8)`.

<a id="r25-t4"></a>
**4. [Классика|hard] Парсер CSV-строки с кавычками.**
`book, second,author,"quoted, comma"` → поля не рвать по запятой внутри кавычек.
```java
static List<String> parseCsvLine(String line) {
    List<String> fields = new ArrayList<>();
    StringBuilder cur = new StringBuilder();
    boolean inQuotes = false;
    for (int i = 0; i < line.length(); i++) {
        char c = line.charAt(i);
        if (c == '"') {
            inQuotes = !inQuotes;             // кавычки в поле не сохраняем (упрощение)
        } else if (c == ',' && !inQuotes) {
            fields.add(cur.toString());
            cur.setLength(0);
        } else {
            cur.append(c);
        }
    }
    fields.add(cur.toString());               // последнее поле
    return fields;
}
```
Состояние `inQuotes` меняет смысл запятой — классический конечный автомат. Обсудить ограничения: удвоенные кавычки `""` внутри поля, переводы строк внутри кавычек — для полного CSV есть библиотека (opencsv, Jackson CSV); на интервью важен сам автомат.
